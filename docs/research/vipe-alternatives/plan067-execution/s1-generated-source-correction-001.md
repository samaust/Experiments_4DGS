# S1 generated Torch source preservation

S1 recovery 007 qualified 510 calibration rows but final acceptance encountered
Torch's generated `_remote_module_non_scriptable.py` after its owned temporary
directory had been retired. Its recorded source identity remains historical;
this correction does not accept or rewrite that attempt.

## Contract

At the first real result, while the owner is live, capture exactly the
`_remote_module_non_scriptable` module into the job's `generated-sources` evidence.
Bind its original path/hash/size, retained path/hash/size, exact module name,
job temporary parent, owned temporary directory device/inode/mount identity, and admitted
Torch instantiator/template file identities. Read literal template text and the
non-scriptable substitution mapping without importing or executing Torch code;
require generated bytes to match that admitted template exactly.

Before cleanup, verify both original and retained bytes and ownership. After
cleanup, runtime acceptance verifies the retained bytes and generator identities;
if the original directory still exists, its original identity and bytes remain
mandatory. Both generator module identities must remain in the loaded manifest.
Unsupported modules, foreign owners, altered/missing copies and missing bindings
are rejected. Ordinary installed files, assets, interpreter and native extension
checks, clocks and cleanup guards remain in force.

## CPU validation

The agreed seam is worker runtime evidence through owned cleanup to supervisor
runtime acceptance, using disposable fake runtime files and a real owned CPU
temporary directory. Eight canonical `s1_recovery` test methods cover successful
live/post-cleanup acceptance, source tampering or loss, ownership and binding
substitution, generator changes, non-template source, and foreign owners.
Together with the seven existing runtime provenance tests, all 15 passed.

A static read of the actual admitted E1 Torch instantiator and template
reproduced **2,355 bytes**, SHA-256
`8205b16956fb264841ecd8644784a0d157f87df79b17c16825dc1163433ce5d8`,
matching the preserved recovery 007 original source identity. No Torch import,
model execution, GPU access, live ledger write or historical artifact publication
was performed. Five changed Python files parsed successfully and `git diff
--check` passed. Integrated review and full qualification belong to the root
implementation milestone.
