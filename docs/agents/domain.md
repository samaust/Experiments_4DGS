# Domain docs

This is a single-context repository. The domain glossary belongs in root
`CONTEXT.md`; architecture decisions belong in `docs/adr/`.

Before domain or design work, read `CONTEXT.md` if present and the relevant ADRs
in `docs/adr/`. Missing files are expected; continue without creating empty
placeholders. Create them when domain terms or decisions need recording.

Use the glossary's terms in issues, plans, code, and tests. If a proposal
conflicts with an ADR, identify that conflict explicitly.
