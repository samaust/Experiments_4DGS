# Plan049 Correction015 source-scope addendum 004 — supervisor descendant retirement

This is a plan-only proposal responding to a concrete gap found while implementing the independently reviewed Correction015 logical-job ledger. It is not adopted authority and does not authorize source edits or execution. Its parent is Plan049 Correction015 plus source-scope addenda001–003.

## Finding and requested narrow extension

The reviewed eight-path scope accounts descendants under their launched process-tree job and adds a special L35 PID-marker/census/pidfd path. Two other existing tests create a nested child which outlives its worker: `SupervisorTests.test_child_survival_invalidates_parent_success_and_is_cleaned_up` and `HelperIntegrationTests.test_real_close_repeated_and_descendant_cleanup`. Both use `nested_worker_code`, whose child is created through `fixture_process_launch` and registered as a descendant. Their existing `supervisor.stop_group` cleanup proves the worker process group empty and waits for the worker, but does not transition the descendant's ledger entry to terminal. The ledger can therefore retain a live child after the test's existing cleanup succeeds.

Add only `scripts/vipe_benchmark/supervisor.py` as a ninth source path, solely to integrate the existing `stop_group` cleanup boundary with the descendant ledger transitions implemented in `scripts/vipe_benchmark/s1_helper_session.py`. The helper-session path is already in the reviewed scope. Keep all current process-group TERM/KILL, wait, return values, deadlines, and assertions. Do not add a test method, callback, process, thread, observer, script, suite, or source member.

Before the first cleanup signal, `stop_group` must ask the ledger for the exact live descendants attached to the exact registered root represented by `process`; PID alone is not sufficient. For each ledger descendant, obtain a live census row and require exact boot ID, PID, start ticks, PGID, and the ledger-recorded creator/ancestry relationship. Open a pidfd and immediately re-read/reconcile those identity fields before treating it as a pinned member. A missing, ambiguous, changed, or unpinnable descendant keeps the job charged and makes cleanup uncertain; it must not be silently dropped.

Preserve the existing process-group cleanup sequence and original deadline. After it returns, require the same group-empty observation, the exact worker handle's successful wait, and terminal readiness on each pinned descendant pidfd. Append exact descendant-retired ledger records only after those checks, then allow the root-tree retirement transition. If a tracked descendant is outside the process group or remains live, cleanup fails closed and remains charged; no deadline is extended. The pidfd witnesses the exact captured process identity only. This mechanism makes no claim of cgroup/kernel-wide containment and must not infer that unknown, unregistered processes are accounted.

The two existing descendant-cleanup tests are the positive integration points. Retain all their assertions and add only bounded checks required to establish that the ledger records each descendant's terminal transition and root-tree closure. The existing L35 fixture remains the release-race control and must continue to pin before its release marker. Existing assertion order/multiplicity, process-group semantics and behavior remain intact.
