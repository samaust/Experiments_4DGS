The current wording does not yet make those two stages an enforceable proof of the command that reaches the syscall.

## Blocking findings and narrow revisions

1. **The template proof is not required to check the expanded command at the launch boundary.** The proposal requires a static map of generator source, substitution types/sources/domains, then says the launch descriptor is “derived from the actual arguments” and validates that descriptor. A descriptor can faithfully record an out-of-domain or differently escaped `-c` program. A source-file hash and a map of intended inputs do not by themselves prove that this invocation used those inputs, that each `repr`/f-string/concatenation produced the reviewed form, or that its nested child command is the reviewed one. Require a pre-create, fail-closed comparison of the actual executable/argv/code to the exact reviewed generator/template and the concrete typed substitution values and provenance for this invocation. Specify the quoting/encoding rule for each substitution and validate the runtime-created path against its authorized attempt-local origin. Apply the check at every selected generated edge, including L35's parent and nested worker, `nested_worker_code`, the cache-worker f-string, and dynamic argument paths. The independent read-only audit must prove the check is implementable within the nine paths without importing or running project code. If a generator/branch cannot be modeled or checked, source closure stays FAIL before editing.
2. **“Relevant environment entries” cannot bind the effective environment.** The actual `Popen` and `os.posix_spawn` calls may pass an explicit mapping or inherit one; an omitted entry can affect Python startup, imports, executable search or child behavior. Require a canonical digest of the *complete effective environment mapping* at OS create, with exact key/value byte encoding and duplicate/invalid-key rejection, while storing only the digest in the ledger. Snapshot any inherited environment before reservation, pass the same private immutable-in-practice snapshot to the creator, and reject a mismatch or unsupported API form before OS creation. Also pin the exact executable argument versus argv[0], the executable-resolution rule where applicable, cwd representation/resolution, and all group/session-changing options. The type-preserving, length-delimited encoding must distinguish strings, bytes and path-like values and bind the bytes actually handed to the OS; `-c`'s claimed UTF-8 bytes must be verified against that encoding or rejected. A post-reservation reconstruction or mutable mapping would leave a gap between descriptor and syscall.
3. **The `-m` module hash must be the current launch-authorized source hash.** The descriptor names “the pre-edit audit's source hash for the resolved project entry module.” The selected `-m` entry set includes edited paths, so a pre-edit hash may no longer describe the code run after the nine-path correction. Require the post-edit exact-source authority/hash for each resolved project entry module, verify its on-disk bytes under the established source gate at launch, and bind that hash to the descriptor. Preserve the audit's pre-edit hash as historical input only. Dynamic module resolution or a changed module must fail the relevant closure/launch gate rather than be described by a stale pre-edit hash.

The reservation protocol also needs its failure branches stated at the descriptor boundary: validation failure before append creates no child and no reservation; an uncertain append/readback blocks the creator and remains conservatively charged; after an attempted OS create, cancellation is allowed only with exact proof that no child was created. Carry the actual descriptor through the existing root/descendant reservation event, including the direct capture B token, and show a finite worst-case per-attempt event/descriptor budget fits the existing 8 MiB ledger cap before implementation. A size-cap rejection must occur before OS creation. These are required accounting gates, not permission to increase the cap or add a sidecar.

## Preserved requirements and review boundary

It retains addendum006's literal repeated `process.wait(timeout=max(.01, deadline-time.monotonic()))` call, the distinct same-handle receipt/creator acknowledgment, readback-first ledger replay, exact owner-incarnation/nonce binding, unknown-signal no-repeat behavior, and legacy no-ledger semantics. The template proof can establish only selected, registered project process ownership; it cannot establish absence of arbitrary OS-level forks or native runtime behavior, and group census cannot replace the transitive code proof. The audit's selected versus merely imported definitions and its `exec(compile(...))` slices still need exact reachability review. None of these retained conditions is certified as implemented or passing by this plan review.
