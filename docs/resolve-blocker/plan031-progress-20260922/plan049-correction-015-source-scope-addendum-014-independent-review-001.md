## Findings on the proposed bounds and gates

The **16,384-byte** ceiling is expressed as a canonical, length-delimited executable-plus-complete-argv bound including `argv[0]` and the actual inline `-c` element. The **1,048,576-byte / 4,096-entry** ceiling covers the full effective environment's encoded key/value bytes before framing; raw values remain out of the ledger. Those are finite fail-closed ceilings and do not themselves change the 8,388,608-byte journal cap. The revised audit must fix the canonical encoding and include its framing, environment entry separators/overhead, descriptor metadata and JSON escaping in the event-size calculation. It must also check per-string and combined operating-system argv/environment constraints for the selected `Popen`, `posix_spawn`, and `execve` forms; a total ceiling alone is no guarantee that one very large value is accepted by the OS. A selected input beyond either cap must fail closed without truncation or omission. These implementation/audit facts are not yet proved by this wording review.

Section 3 correctly demands a finite maximum count for **each event kind**, including bootstrap/Main handle, all selected nested/direct-script/aggregate creations, success and coexisting failure/recovery branches, and identity/wait/signal/close/retirement/finalization records. It requires exact serialized event lengths and a concrete whole-ledger integer ≤8,388,608 before editing. The current audit002 supplies no such count or numeric total; the existing append-time cap is not a substitute. The phrase “maximum existing serialized ledger history” should be made a disjoint baseline term or counted once inside the event-kind sum, so the arithmetic is reviewable and does not silently double-count or omit existing events. Any unbounded label, integer, identity, timestamp, environment or argv field keeps the gate FAIL. The proposal correctly refuses a cap increase if the proof fails.

The L35 pre-edit patch-review route is explicit in sequence: an independent static audit reviews an exact proposed change within the nine paths, proves its command template and affected path provenance without applying/running the patch, and a distinct exact-source review follows the authorized edit. That can resolve audit002's current `TemporaryDirectory()` failure while preserving the pre-edit gate, provided the next wording fixes the root-domain/authority questions above. The proposal retains addendum013's independent render comparison immediately before reservation and OS create, immutable complete environment handoff, final post-edit `-m` hashes, descriptor-bearing durable reservations and readback-first failure rules as source-stage obligations. It does not certify their implementation.

The proposed sequence preserves Plan049's original deadlines and assertions, the nine-path edit limit, 78/249/1,028 counts, CPU-only serial execution, `B+max(1,H)≤8`, 150 GiB artifact and 64 MiB memo limits, and addenda006/011 same-handle wait and ownership/cleanup rules.
