## Reservation failure and numeric 8 MiB gate

`JOB_LEDGER_LIMIT=8*1024*1024=8,388,608` bytes (`s1_helper_session.py:29`). `_job_line` serializes one JSON event at `:36-40`. `append_job_event` computes `len(raw)+len(line)>8,388,608` before `os.write`, then fsyncs and rereads (`:185-207`). Thus a known oversize event is rejected before that append. The current reservation event contains no descriptor, and the current `create_owned_process` proceeds after `reserve_job_root` returns. The new requirement to decide and record command/template/environment fields before create, handle uncertain append/readback without duplicate create, and distinguish a definitely absent child from an ambiguous create exception is not implemented.

**Whole-ledger maximum: not finite under current validated inputs; no ≤8,388,608 proof.** `env=dict(os.environ,**settings)` and `os.environ.copy()` have no selected-source maximum number of keys or total bytes; `create_owned_process(...,**kwargs)` and generated `code` arguments have no common maximum encoded length. Even one proposed complete environment descriptor cannot be assigned a finite worst-case encoded size from these sources. Therefore the arithmetic is `existing maximum (unproved) + additional descriptor maximum (unbounded)`, which is not a finite number ≤8,388,608. The 249 methods/1,028 callbacks are fixed collection counts, not a per-callback creator/event or byte bound. The append-time cap can stop an overlarge run; it does not prove the entire selected attempt fits. Before PASS, the audit needs explicit maximum validated argv/env lengths, a finite creator/event count across all selected methods/scenarios/direct scripts, exact maximum canonical serialization per event including existing owner/wait/signal/close records, and a numeric sum below 8,388,608. Raising the cap or assuming typical environment size is outside addendum013.

For the future source correction, validation failure must produce zero reservation events and zero creates; uncertain reservation append/readback must stop creation and stay conservatively charged until exact readback resolves it; a create exception can cancel only on exact no-child evidence; after a returned handle, bind/ack failure stays charged with that handle retained.
