# Independent follow-up — Correction016 paths and hash order

**Verdict: vacant-path correction is sound; hash order still needs correction.** I reviewed [Plan049](../../../plans/plan_049.md) at SHA-256 `046b60b78e65841dd0b9d9b7ec6c25b18d33ef465619c05d26f07cb1fe6962cf` and [Correction016](plan049-correction-016.md) at SHA-256 `c2ed0600da62de8512641d94ea975abd3f2ae97bdec50d311005395f702c05b7` against the current launch driver and validation contract. This was a static review only; no code edit, test, import, launch, prompt read or commit occurred.

The revised vacant-path protocol resolves the first design comment. Before admission it binds six absolute child-path strings and checks vacancy without creating the attempt directory. Current `launch-049-exec.py` rejects an occupied attempt directory, and capture creates it with `mkdir(..., exist_ok=False)`. Creating lane children exclusively *after* capture creates that parent is compatible in principle. Exact symlink, alias, source and output ownership checks remain a future reviewed implementation gate.

The stated hash order does **not** resolve the second comment against current Correction008 authority. Correction016 and Plan049 §8 say `manifest → admission → session proof → lane receipts → index`, and Correction016 says the proof references an **admission digest**. Current `launch-049-exec.py` requires admission `bindings.session_proof` to be the strict `{path,bytes,sha256}` record of an already written proof; `s1_validation_contract.no_timeout_launch` enforces that binding. The current proof contains the prospective `admission_path` string, not the later admission's digest. Putting the admission digest in proof while admission binds the proof digest creates a cycle. Correction016's later wording that the manifest binds “one fresh admission/session proof” is also ambiguous if it means their file digests before either exists.

The compatible acyclic direction is: freeze/hash the canonical source and lane manifest without later-record digests; create/hash session proof using the fixed prospective admission **path**; create admission binding the strict proof and manifest records; then issue lane receipts binding the admitted manifest/proof identity and a final index binding completed receipts. An exact schema must still settle prospective paths versus strict records, readback and freshness before ADMIT. Until that decision-complete amendment is reviewed, the manifest/anchor gate remains open.

Both documents still explicitly confine Correction016 to conditional planning, preserve `B+max(1,H)≤8`, original behavioral deadlines and serial final acceptance, and keep P16-1, shared ownership gate and C1–C3 as launch stops. The incorrect hash order does not silently authorize a launch; it prevents treating the proposed protocol as ready.
