## 2. Per-string OS limits and identity fields

Retain the 1,048,576-byte aggregate environment limit and 4,096-entry maximum from addendum014, but add an independent per-string gate. For every environment entry, check the encoded `key=value\0` byte count against the smallest selected OS API per-string limit, including the terminating NUL. For argv strings, include their NULs too. Check the combined argv+environment size, pointer/count overhead, and the target's `ARG_MAX` before reservation. On the reviewed Linux host, the observed `MAX_ARG_STRLEN` is 131,072 bytes including NUL; this is a host observation, not a portable constant. Fresh preflight must obtain the current authorized host's per-string and combined limits from read-only OS interfaces available in the already-counted Main/driver process (for example, `sysconf` for `_SC_ARG_MAX`, page size, and an explicitly reviewed Linux per-string rule); it must not spawn `getconf` or any helper. Recompute these values in the driver immediately before its first filesystem mutation. Missing or unsupported limits block before reservation. Apply actual host limits per rendered string and to the combined rendered vector with pointer/count overhead; the 16,384-byte argv and 1,048,576-byte environment totals are independent policy ceilings, not assertions that one string must reach that size. A smaller host limit is acceptable only when every actual rendered string and combined vector is proven to fit; otherwise fail closed. Do not infer a per-string guarantee from aggregate environment bytes.

To make per-attempt ledger arithmetic finite without adding an attempt-count cap, bind the **exact current candidate index** during read-only high-water preflight and calculate its decimal width `d(index)`. Validate the exact prospective `attempt-open` serialized size, using that candidate and the maximum permitted remaining ledger, before appending bootstrap. Recompute this proof for every later candidate; do not impose a global maximum index or attempt count. If the candidate-specific whole-ledger maximum exceeds 8,388,608 bytes, do not create that attempt's ledger or admit tests.

The tool session handle remains the exact positive integer returned by Main's exec-session interface. Proposed maximum decimal width is **16,384 digits**; reject a longer handle before `ADMIT` or tests, keep the live session charged, and retire it only through the exact returned Main handle. This is a bounded evidence-field policy, not a timeout or attempt-count cap. Process/thread IDs and start ticks must use a finite host/platform-derived maximum read during preflight and rechecked at each binding; Python object IDs use the host pointer-width maximum. Timestamps use a fixed-width UTC representation. Any missing bound, noncanonical number, or unsupported platform form blocks the pre-edit arithmetic and later source implementation.
