# Plan049 Correction015 source-scope addendum 013 — verified command rendering and complete launch context

## 1. Read-only template proof

Before editing, the independent static closure audit enumerates every selected process/thread creation and dynamically constructed command. For every generated argv or inline program, it records the exact source hash and call-site range, a canonical literal template with uniquely delimited slot names, every slot's exact type/source/allowed domain, and the escaping rule used to render the slot into argv/code bytes. It includes L35 marker/release paths, nested child argv, `nested_worker_code(seconds,parent_wait)`, the cache-worker f-string, dynamic direct-script selectors, and every `exec(compile(...))` slice that can affect launch behavior. The audit proves that the values come only from the exact selected callsite and authorized temporary/repository roots, and that the template cannot select a different import, command, group/session mode, or nested creator. Resolve and hash all reachable project modules; for any `-m` entry module the audit binds the pre-edit hash as history, while implementation and launch authority later use the final post-edit exact-source hash. Unsupported dynamic/environment inputs or an unmodelled creator are a closure FAIL before source edits.

The review binds both the template and the canonical slot schema. Runtime checking must not rely solely on the command's self-reported digest or on reusing the same string-building expression twice.

## 2. Pre-create rendered-command verification

In existing authorized call paths only, pass a command-authority record to the existing process creation gate. It contains the reviewed template identifier/hash, canonical template bytes, typed substitution values and provenance handles, and the expected complete argv shape. The gate uses a fixed, unambiguous slot renderer (unique delimiter tokens; one pass; no recursive replacement; exact UTF-8 or filesystem encoding specified per slot) to independently render expected argv/code from the canonical template and values. Immediately before reservation and again immediately before the OS create, it compares the immutable executable argument, full argv vector and exact `-c` bytes passed to the creator against that rendered expectation; it also validates each path slot is beneath the exact authorized attempt-local root and has the required canonical resolution. The implementation must enumerate all generated sites from the audit and show each passes this authority record; unsupported creators or authority-less generated commands fail before OS creation.

For each command vector, canonical encoding is versioned, type-preserving and length-delimited. It binds the distinct executable argument and argv[0], every argv element (including exact `-c` bytes or `-m` module), resolved cwd, `start_new_session`, process-group/session flags, and the executable resolution rule. Strings/path-like values must be converted with a single specified filesystem encoding; bytes retain their exact bytes. Reject NUL, embedded invalid argv/environment forms, unknown option types, and ambiguous shell modes. These records identify the attempted launch; they are not process identity, terminal, or ownership evidence.

## 3. Complete effective environment snapshot

Before reservation, construct one private immutable-in-practice snapshot of the complete effective environment mapping. If the creator would inherit ambient `os.environ`, snapshot the full POSIX byte environment (`os.environb`) and pass that same snapshot explicitly. If the callsite supplies an environment, canonicalize and validate every key/value using exact OS bytes, reject duplicate keys, invalid names, NUL and unsupported values, then pass the same captured mapping object to the creator. Hash the complete key/value set with a deterministic sorted, length-delimited encoding and store only the digest and count/encoded-byte length in the reservation. An unsupported platform/API form, unbounded mapping size, mutation after capture, digest mismatch, or inability to pass the exact same captured environment fails closed before creation. Do not hash only selected “relevant” keys or re-read the environment after reservation.

Bind executable resolution/cwd and group/session-changing options with the environment descriptor. In particular, `subprocess.Popen` and `os.posix_spawn` must receive exactly the recorded executable/argv/environment/cwd/options. Immediately before the OS call, verify the command and environment have not changed. The current final source manifest/hash (not the pre-edit closure snapshot) supplies the `-m` project module content hash; module resolution must match that fixed module and exact final bytes.

## 4. Durable reservation, failure, and cap handling

For managed B roots and descendants, include the complete command/environment descriptor and command-authority/template ID in the existing root/descendant reservation event. For direct capture Popen, bind its reserved B token the same way before `Popen`. Append/fsync/read back this reservation under the existing 8 MiB ledger cap **before** OS creation. Compute the exact serialized event size and reject a cap overflow before the create syscall. Before implementation, the source closure report must calculate a finite per-attempt worst-case number and byte size of all additional descriptors/events using fixed selected callback/scenario counts and maximum validated argv/env lengths; prove the whole ledger remains under the existing 8 MiB limit without raising it.

If command/template/environment validation fails, no reservation is appended and no child is created. If reservation append/readback is uncertain, do not call the creator; retain a conservative unresolved charge/stop state until exact journal readback resolves whether the event exists. If the OS create operation raises before returning, cancellation is allowed only with exact evidence no process was created; otherwise leave the reservation charged. After successful creation, identity bind/creator acknowledgment follows existing rules; any failure leaves the exact reserved descriptor/charge unresolved and the returned handle available for cleanup. No PID/argv hash substitutes for identity or terminal proof.
