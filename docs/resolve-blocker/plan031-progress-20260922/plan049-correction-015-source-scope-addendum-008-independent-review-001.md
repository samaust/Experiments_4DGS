# Plan049 Correction015 source-scope addendum008 — independent plan review 001

**Verdict: NEEDS_REVISION. NO SOURCE OR LAUNCH CLEARANCE.** Addendum008 fixes addendum007's obvious reserve-before-create gap: a pre-stop reservation remains charged, prevents all signals and retirement until an exact creator outcome is durably acknowledged or creation is proved absent, and requires a fresh locked snapshot. It also supplies the missing `live -> stopping -> waited -> retired` replay path, preserves the already-retired signal-free path and legacy group behavior, and requires immediate checks against the original absolute deadline. The following ambiguities still prevent an exact plan PASS.

1. **Concurrent exact-handle wait is not serialized.** Two callers can both read `stopping`, each wait on the same retained process handle, and only then attempt `root-wait`; neither observes a durable terminal at entry. The stated “at most once” rule and reuse of an *already recorded* terminal do not resolve that race. Specify one durable/in-memory wait owner or single-flight protocol before entering the wait, how a contender receives the exact terminal, and what happens if the wait succeeds but append/readback fails or the owner disappears. Do not infer terminal success from `stopping`, wait a second time, or retire without the matching durable terminal. Define the retry path for a root that exits during pin acquisition under the same rule.

2. **The creation inventory does not yet establish complete logical-tree closure.** A static inventory of entrypoints in the nine selected files is a useful source gate, and addendum008 correctly disclaims OS containment. It must also account for code executed by created children (including subprocess commands and fixture programs) that can fork, start a child in another group, or leave a member after the census. Otherwise an escaped child can be absent from both group censuses and the ledger, with no “evidence” of escape to trigger the stated fail-closed rule. Define the bounded transitive creator/code inventory and the exact proof that all such creation paths use the reservation protocol, or explicitly limit retirement to registered members and leave any unprovable full-tree claim charged. If that proof cannot fit the frozen nine-path scope, invoke the proposed narrow amendment gate; a passing census alone cannot supply it.

3. **Partial signaling and uncertain descriptor retirement need a replayable rule.** “Track per-target signal progress” and “retry may repeat an idempotent signal” do not identify the durable state of a successful, failed, or outcome-unknown TERM/KILL send after another target has already been signaled. Repeating TERM can invoke a handler again, so do not call it idempotent without an explicit process-level guarantee. State whether a send failure stops the remaining sends, how each outcome is retained across same-handle retries, and how a retry acts only on targets whose exact signal/terminal state is known. Likewise, `close` uncertainty discovered *after* durable root retirement cannot keep that root charged under the stated graph; specify whether close is a separate local-resource uncertainty, or move the required close proof before retirement without permitting a retry on a possibly reused descriptor. Keep the original TERM grace, absolute deadline, immediate pre-send/pre-wait checks, and cleanup-error precedence.
