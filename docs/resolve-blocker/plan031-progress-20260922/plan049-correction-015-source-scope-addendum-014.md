## 2. Finite input ceilings

For the selected launch set, propose the following hard ceilings on the canonical OS-byte inputs, inclusive of every slot after rendering:

- Complete executable-plus-argv descriptor: at most **16,384 encoded bytes total** per OS create. This covers the executable separately, `argv[0]`, all argv elements, and exact inline `-c` bytes using the canonical length-delimited encoding. No individual argument may exceed the total.
- Complete effective environment: at most **1,048,576 encoded key/value bytes total**, with at most **4,096 distinct entries**. Count lengths after the specified filesystem encoding and before environment framing. The complete captured mapping must be immutable for the create transaction, hashed, and passed unchanged; do not persist raw environment values in the ledger.

These are fail-closed input caps, not truncation rules. If validation proves before reservation that an authorized selected environment or rendered command exceeds a ceiling, create no reservation and no child for that operation; stop that selected work while preserving prior records and charges. Do not invent an unresolved child charge when no reservation or OS create was attempted. Retain addendum013's conservative unresolved handling only for uncertain reservation append/readback or an OS create outcome that may have created a process. Never omit variables, clip arguments, or silently change the command to fit. The revised audit must check every exact selected template and source of substitution against these ceilings, including environment composition in the driver/capture/helper edges. It must establish compatibility with the selected creation interfaces without assuming ambient inputs have typical sizes. In particular, prove both each argument/environment string and the combined encoded argv+environment (including terminators, pointers/overhead required by the selected OS APIs) are within supported OS limits on the authorized host; fail closed if the platform/API limit is unavailable or smaller than the proposed ceilings. The two numeric values are proposal values only until independently reviewed and user-authorized.
