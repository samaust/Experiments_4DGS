Enumerate the complete fixed-file set with exact path/hash/bytes, or bind a closed manifest and its hash, and state how the current source and later exact-source review use it. Keep fixed authority inputs read-only and distinct from new run evidence.
2. **The domain-disjointness sentence contradicts the new class.** Section 1 says “A direct `R` child cannot be relabeled ... `run_authority_path`,” but several intended authority files, including `R/implementation-dispatch-049.json`, `R/implementation-status-049.md`, `R/authorization-049.md` and correction/addendum records, are direct children of `R` (`launch-049-exec.py:109-113,228-246`). Restrict that prohibition to a direct child whose exact filename is in the *run-evidence* allowlist; define disjoint sets of evidence, authority and status names. Keep `R/status.md` in its one fixed Main-only domain. The creation-time vacancy clarification for evidence is correct: later reads must check the same file identity/content, not continued vacancy.
3. **Make the pre-sidecar host/high-water proof's data source explicit.** Section 4 narrowly supersedes addendum001's “first action” for pure read-only candidate-index, prospective size and host-limit validation, then says those computations perform **no filesystem access** before the exclusive sidecar's first filesystem mutation. Yet §2 requires fresh high-water candidate and current authorized host per-string/combined limits from a trusted source. The driver can do pure arithmetic before sidecar creation only if Main's prior read-only preflight supplies those exact values in a separately hash/session-bound form, or the plan can explicitly permit read-only filesystem/host-metadata access inside H before the first mutation. State which actor obtains/rechecks the inputs, when, and how the driver binds them to the exact candidate/host. Preserve the charged H handle and no-sidecar/no-admission outcome on failure. Do not silently treat a stale Main value or a file read as a pure computation.
