## Failure and correction

The observed orchestration bug was in Main's `functions.exec` JavaScript wrapper: after `await tools.exec_command(args)` returned, the wrapper referenced unavailable `crypto` while hashing **before** saving or displaying the raw nested result. The wrapper raised `ReferenceError: crypto is not defined`, losing the full return and exact session handle from that isolate. This is a result-capture/order failure; it does not prove that the nested driver failed or terminated. No source-code defect in the Plan049 driver has been established by this event.

The adopted operational fix for a separately cleared future launch is a dedicated `functions.exec` cell whose only post-return operations are, in order, `const r = await tools.exec_command(args); store(uniqueAttemptKey, r); text(r);` and cell completion. The `store` receives the **full raw nested result**; the raw full result is immediately emitted with an output budget large enough to display it completely. Prelaunch checks and preparation precede the cell. No hashing, formatting, JSON event construction, file persistence, UTC conversion, polling, second launch or other fallible step may occur before both store and emit. After successful outer-cell completion, Main must inspect the complete original visible result, confirm its exact positive bounded `session_id`, compare later `load` and value-preserving v2 file readback to that original, and use only that same handle for every permitted later session operation. Any failed store, emit, outer completion, missing/truncated visible output or mismatch leaves the new attempt unresolved and charged. `store` is session-local, not durable independent attestation or atomic escrow: the interval after nested return and before successful store/emit remains a residual loss window.

A read-only host-census wrapper exercised `store` then raw `text` without `crypto`; its synchronous nested return had no long-running `session_id`. That checks this limited wrapper ordering, **not** live-session capture, exact-handle visibility, reattachment or retirement. It is no substitute for a reviewed future original result.
