## C. External cap/partial-tail reporting slot

C3 cannot PASS on the historical sample alone.

The measured append rule remains `S+L≤8,388,608` under the exclusive lock after exact on-disk prefix/readback; equality is allowed, over-cap is rejected **before** append. If rollback/readback fails, preserve bytes without further mutation, report verified prefix `S`/hash, attempted `L` and observed errors; report tail bytes/hash only if actually read and verified, otherwise unknown. No new append/admission/retirement or next attempt follows until independent reconciliation. This is a design requirement, not implemented source behavior.

## Disposition

The exact selected source exposes fixed strings and six literal selector pairs, but it does **not** produce the missing C2 numerical/static closure: no versioned descriptor grammar, per-inline-code rendered fixed-byte table, candidate-specific byte substitution with finite random-temp/ambient-env bounds, immutable per-create snapshots or supported host overhead proof. A future candidate's unknown digit width is **not independently a blocker**: derive its exact `d(i)` from fresh high-water before that candidate's first mutation and redo the static inequality. Nor does current source yield C3's final event names/closed fields/emitters/one-shot results or an already bound Main cap-report schema. These are precise FAIL conditions, not a request for changed caps/scope/deadlines and not a theoretical ledger-sum complaint. Preserve all original assertions/deadlines/error precedence/selector order, the exact nine-path source scope, 78 members/249 methods/1,028 callbacks, serial CPU-only `B+max(1,H)≤8`, 150 GiB artifacts, ≤64 MiB memo, 8,388,608-byte ledger, 16,384-byte descriptor, complete 1,048,576-byte/4,096-entry environment and fresh host limits. No operational time/attempt/correction ceiling is introduced. No source edit/import/test/fixture/process/pidfd/admission/diagnostic/launch/aggregate is cleared. Never read `prompts`; resource use is unknown where not measured.
