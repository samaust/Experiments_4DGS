## 1. Selected command encoding and finite calculation

Propose canonical byte descriptor `plan049-command/v1\0`, then in this **fixed order**: `api:u8` (`1=execve,2=Popen,3=posix_spawn`); `executable:bytes32`; `argc:u16be`; `argc` repetitions of `argument:bytes32` including distinct `argv[0]`; `cwd_tag:u8` (`0=inherited,1=resolved`) and a `bytes32` resolved cwd only for tag1; `option_bits:u16be` for exact session/group/stdin/stdout/stderr/shell modes; `action_count:u16be` and fixed-order file actions, each `action_code:u8`, `fd1:u32be`, `fd2:u32be` (unused fd2 encoded as zero); `template_sha256:32 raw bytes`; `module_sha256:32 raw bytes` or 32 zero bytes for no `-m`; `env_count:u16be`; `env_keyvalue_bytes:u32be`; `env_sha256:32 raw bytes`. `bytes32` is `length:u32be || exact POSIX bytes`; source strings use `os.fsencode` once, already-byte values stay bytes, NUL or unsupported encoding fails. `option_bits` and action codes must be enumerated from selected calls before audit PASS; no unknown bits. The descriptor contains every actual argv/code byte and the complete environment **digest/count/byte length**, consistent with Addendum013 §3/4; full immutable environment bytes remain available to the create gate and its pre-/post-reservation equality check. The environment digest stream is `plan049-env/v1\0 || envc:u16be || Σ(key:bytes32 || value:bytes32)` sorted by byte key; duplicate/invalid key, `=` in key and NUL fail. The descriptor framing overhead is mechanically determined by these fields; a passing audit must calculate its integer `D_fixed` for **each selected caller** and ensure the whole descriptor including path/inline-code bytes is `≤16,384`. This document does not assert an uncomputed integer.

The [matrix §A](audit006-c2-c3-source-matrix.md#a-exact-selected-os-create-templates-and-unresolved-bounds) supplies the actual caller IDs: Main tool-to-driver; driver `execve`; capture `Popen`; production Owner `work|sample`; fixture FaultOwner `work|sample`; fixture descendant; supervisor success/cache/timeout/nested/`pass`/interruption/resource-error branches; race worker; helper probe/test worker; nested `(20,False)` and `(10,True)` outer/inner; scenario sentinel `sleep(10)|pass`; L35 outer/inner; L18 sentinel; direct D1–D6; native/budget threads (which have **no** process descriptor). Generic helper parameters do not add arbitrary selected vectors; each actual caller must have a separate row in the independent source audit. The literal code is the source string expression at the cited line, rendered **once** with typed values: `repr([P/scripts,P/tests])` for nested; `repr(P/tests)`, `repr(T/ready)`, `repr(T/release)` for L35; `repr` of the six fixed cache names for cache worker. The exact materialized bytes and escaping of all such `repr`/f-string outputs, including each selected success/timeout/error `C`, must be tabulated; a generic `C` or substring estimate is not acceptable. D1–D6's exact suite/selector strings are recorded in the matrix and each needs its own `D_fixed`, not a single maximum inferred from the longest visible spelling. The focus uses the actual L01–L36/P01–P06 branches, while the aggregate additionally reaches earlier SupervisorTests variants; D6 patches `Session` and does not itself prove real Owner creates. No new method/selector/callback is proposed.

For fresh candidate `i`, substitute `d(i)=max(3,decimal_digits(i))` from read-only exhaustive high-water and exact current `A`; there is **no attempt-count cap** or universal future digit ceiling. Recompute candidate-specific path/command inequalities before the driver's first mutation, then validate actual bytes before each reservation and equality/fresh host limits immediately before each OS create. Main's exact returned positive handle is checked at `≤16,384` digits and bound to the same H/terminal/retirement path. If the fresh candidate or handle does not fit the existing descriptor/ledger/schema constraints, fail closed without changing selector or original deadline.

For `TemporaryDirectory()` with default prefix/suffix, the selected local stdlib `/usr/lib/python3.11/tempfile.py:209,254-267,272-294,500-531,1009-1010` (SHA-256 `5ee9804e23b46fcd68991b9da825b63b28580258fae2d69fc8c128768ddb1a86`) shows basename `tmp` plus exactly eight characters from `[a-z0-9_]`, with empty suffix. Thus `|T|≤|effective_temp_base|+1+3+8` **for this exact stdlib/default call** (the separator is already present if base ends with `/`), provided the selected base is encoded and canonical. Calls with explicit `prefix`, `suffix` or `dir` use those exact caller values instead; no universal eight-byte assumption. The prospective design must hash-bind that stdlib behavior at preflight, derive an allowed base maximum from the **existing** descriptor/host ceilings for every selected path and reject longer bases before any dependent reservation/OS create. Its numerical per-caller allowance has not been calculated, so C2 is still FAIL. No `TemporaryDirectory` name or retained owner can be replaced with an invented fixed `/tmp` path.

The complete final environment is bounded only **after** source-order overlays and removals: driver `E0 + six CPU values + PYTHONPATH − two diagnostics + note/hash/ledger`; capture `E0 + ENVIRONMENT − None keys + diagnostic receipt + A`; Owner `E0 + PYTHONPATH + four THREADS + OPENCV`; FaultOwner adds tests path; supervisor `E0 + reservation/thread/offline + optional S1 clock JSON + TMPDIR + six cache paths + progress-context JSON`; helper probe `E0 + PYTHONPATH`; scenario `E0 + OPENCV`; direct D1–D6 `E0 + ENVIRONMENT − S1_VALIDATION_RUN_DIRECTORY`; inherited-env descendants and test workers capture **all** E0. These are per-caller overlays from the matrix, not a filtered set of “relevant” keys. Use exact immutable POSIX byte snapshot and the **same mapping** at OS create. Let `K=envc≤4096` and `Q=Σ(|key|+|value|)≤1,048,576` for the final mapping. Then the exact NUL/equal-sign OS environment bytes obey `E_os=Q+2K≤1,056,768`; every individual `|key|+1+|value|+1` must separately obey fresh host `MAX_ARG_STRLEN`. Per-caller pre-edit closure must still prove overlay key/value bytes, path/JSON slot maxima, no collision/duplicate semantics, and that the final capped snapshot is the object actually passed. A large inherited value can fail the per-string rule even when Q passes.

For OS vector, `A_os=Σ(|arg|+1)` for actual argv, `E_os=Q+2K`, and the exact selected API/host requires `A_os+E_os+P_host(argc,K,api,platform)≤fresh ARG_MAX` plus every NUL-inclusive string `≤fresh MAX_ARG_STRLEN`. The descriptor includes argv bytes, so `A_os` can be bounded from its final `≤16,384` bytes plus `argc` NULs; `argc` is `u16` but the actual selected maximum still needs a caller row. `P_host` must include the host/API's pointer tables, terminators and auxiliary/kernel reserve, with source evidence; it cannot be guessed as zero or an arbitrary safety margin. Audit006's observed host `ARG_MAX=2,097,152`, pointer width8 and `MAX_ARG_STRLEN=131,072` are not future-host authority. This proposal does not contain a reviewed supported `P_host` derivation or numerical per-caller `A_os`, so the C2 static inequality is **not yet closed**. Runtime materialized checks remain mandatory and do not cure that gap.

## 2. Proposed closed event vocabulary; schema cells still requiring evidence

Every event retains common keys `schema,sequence,previous_sha256,utc,event,data,sha256`, canonical sorted compact JSONL and newline. The proposed typed `data` rules below retain every current key in [matrix §B](audit006-c2-c3-source-matrix.md#b-exact-current-ledger-emitters-and-missing-prospective-schema). Each operation has `operation_key` derived from `(boot_id,owner_pid,owner_start_ticks,main_session_id,root_token,owner_nonce,handle_object_id,target_token/identity,operation,phase)`; the owner registry installs the fresh nonce under its lock and validates same live incarnation and exact object. The root mutex survives through retirement or uncertainty. Under the interprocess lock, readback-first matching key/payload consumes one receipt, conflicting payload/duplicate fails; claim fsync/readback precedes its one syscall; result is cached by the live exact owner before result append; lost/unknown result leaves B/H charged and forbids retry or later target action. The final numeric-width and byte maxima for process identity, census, terminal variants, owner nonce and operation-key encoding are **not** in current source or this proposal, so this table is a design attempt, not a passing closed schema.

## 3. Main cap/uncertain-tail external evidence binding attempt

The existing exact direct-`R` terminal family `main-launch-terminal-049-{kind}-{index}.json` is the proposed **sole** durable Main cap/partial-tail failure record, with `kind=diagnostic|aggregate`, fresh positive minimum-three-digit index, canonical direct parent R, terminal phase only, exclusive vacancy and same-file readback. Historical `main-launch-terminal-049-diagnostic-005.json` (SHA-256 `fb38dba716bd2d94afdd655e6ab43c915675e96380c67fc323f8a9fa9a333252`) has `schema='plan049-main-launch-terminal/v1'`, exact Main session/proof/admission/send/poll/outcome references and observed exit/test/child fields. A prospective `v1` failure variant would preserve those existing fields **when those events occurred**, with a new required typed `ledger_failure` object: `kind='cap'|'short_write'|'rollback_or_readback_uncertain'`, `verified_prefix_bytes`, `verified_prefix_sha256`, `attempted_line_bytes`, `operation_key`, `main_session_id`, `write_error?`, `truncate_error?`, `read_error?`, `tail_bytes?`, `tail_sha256?`, `tail_unknown`, `charged_B`, `charged_H`, `next_action='stop'`. Tail bytes/hash are allowed only if actually read and verified; otherwise `tail_unknown=true` and those fields absent. The exact current `S+L≤8,388,608` lock/readback/append rule, successful rollback-and-stop, failed rollback preservation and no emergency over-cap row are unchanged.

This is **not yet a complete v1 schema**: no adopted authority specifies how absent proof/admission/send/poll/outcome/child fields are represented when the cap stops *before* those phases, nor a selected Main writer for the failure variant, and a terminal file may itself be unavailable after a filesystem error. Do not fill absent fields with false success, invent a sidecar, or overwrite a preexisting terminal. Main's live transcript is the fallback only when durable terminal reporting cannot be completed; it states last verified S/hash, attempted L, observed errors and each unreadable current/tail fact as `unknown`. No later admission/append/retirement or next attempt follows unresolved charged ownership. An exact conditional field schema and Main writer binding must be reviewed before C3 PASS.
