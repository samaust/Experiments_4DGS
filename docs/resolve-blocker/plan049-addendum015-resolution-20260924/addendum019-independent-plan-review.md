## Required corrections

1. **Keep C2's pre-edit finite command/environment proof.** The authorization note records the user's request to optimize, implement, use, measure and review ledger size; it explicitly interprets that direction as superseding only the exact theoretical *whole-attempt ledger* maximum. Addendum014 §2/§4 and adopted Addendum016 §2 require a pre-edit typed renderer with each selected template's static byte contribution, finite dynamic-slot maxima and prospective worst-case canonical command/environment feasibility under the existing 16,384-byte descriptor, 1,048,576-byte/4,096-entry environment and host limits. Addendum019's “Exact selected command and environment checks” says the actual per-create check “replaces only universal *pre-edit* maxima,” and Plan052 M1 omits those finite maxima. Runtime checks on actual immutable candidates are also required, but they cannot replace the separate prospective C2 proof under the authorization supplied here. Revise Plan052/Addendum019 to retain the pre-edit static template, slot, environment and host-feasibility bounds plus the actual pre-reservation/immediate-pre-create equality checks. If that C2 proof cannot be closed, the prospective audit remains FAIL and source editing remains blocked; a separate explicit, reviewed authorization would be needed to change that gate.
2. **State uncertainty without promising unreadable bytes.** The committed-prefix protocol correctly rejects `S+L>8,388,608` before append, allows equality, holds the lock, renders a complete canonical row, fsyncs and verifies readback, and stops after an ambiguous write. Rolling an uncommitted partial tail back to the verified `S` offset is a reasonable candidate if the original prefix is then fsynced and reverified. But the sentence requiring the on-disk uncertain tail's “bytes and hash” if rollback/**readback** fails overclaims what can be known when reading fails. Require preservation of the file without further mutation and report the last verified `S`/hash, the attempted `L`, observed write/truncate/read errors, and the tail bytes/hash **only if actually read and verified**; otherwise mark physical tail size/content/hash unknown. Maintain the charge and stop further append/admission/retirement. Plan052 M5's observed-content report should likewise allow explicit unknown fields for an unreadable stopped attempt. A partial physical tail must never be described as a committed row or silently discarded.
3. **Clarify the two mutation boundaries.** The command section says to recheck “after reservation and before mutation,” though ledger reservation is itself a filesystem mutation. Require the actual command/environment validation before reservation, then an equality recheck immediately before the OS create after the durable reservation. Separately retain the driver's read-only candidate/high-water/host/authority checks before **its first** filesystem mutation, the exclusive ledger sidecar. This avoids interpreting the text as allowing unchecked reservation writes.
