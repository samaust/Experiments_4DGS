## 1. Candidate C2 byte layout, subject to exact caller proof

A possible deterministic command descriptor can use only already authorized bounded inputs, without storing raw environment values in the job ledger. Define a candidate byte stream `b'plan049-command/v1\0'` followed by fixed-order typed fields. Each field is `tag:u16be | payload_length:u32be | payload`, where tags are a reviewed fixed enum and payloads use one selected filesystem encoding with no NUL. Required fields are API (`execve`, `Popen`, or `posix_spawn`), executable bytes, `argc:u32be` and each length-delimited argv byte string **including distinct `argv[0]`**, resolved cwd or an explicit inherited-cwd sentinel, `start_new_session`/`setsid` booleans, exact file-action/stdin/stdout/stderr option tuples, typed path-domain/provenance identifiers, and the 32-byte digest, count and encoded-byte length of the complete effective environment. Fixed ordering and lengths prohibit recursive substitution or ambiguous concatenation. A future source design would independently render this byte stream from reviewed literal templates and typed slots, compare it to the actual selected OS create before reservation and immediately before create, and reject any value above the existing **16,384-byte descriptor ceiling**. This is an implementation-choice sketch, **not** a derived byte maximum: tag values, every option tuple, per-caller literal contribution, placeholder escaping, and every selected `-c` body remain to be enumerated and independently reviewed before C2 can PASS. The source must retain the executable/`argv[0]` distinction and bind final post-edit `-m` module hashes.

For a candidate full environment snapshot, take exact POSIX bytes at each existing create boundary (or fail closed if unavailable), apply the already selected ambient/driver/capture/helper/supervisor/test overlays in their source order, reject duplicate/invalid names and NUL, sort byte keys for digest framing, and pass the **same immutable captured mapping** to the OS call. A candidate digest stream is `b'plan049-env/v1\0' | envc:u32be | Σ(key_length:u32be | key | value_length:u32be | value)`. The policy aggregate is `E_keyval=Σ(|key|+|value|)≤1,048,576` and `envc≤4,096`; OS string accounting separately uses `E_os=Σ(|key|+1+|value|+1)` for each `key=value\0`. Every argv string uses `|arg|+1` including NUL. For the actual host/API, require each string ≤ the reacquired per-string limit and `Σ(|arg|+1)+E_os+P_host(argc,envc,selected platform overhead)≤ARG_MAX_host`, in addition to the independent descriptor cap. `P_host` must be a documented exact or conservative host-supported overhead formula, including pointer/count/auxiliary terms; Audit005's loose `1,253,392` estimate and historical `ARG_MAX=2,097,152`/131,072-byte string observations are **not** such proof.
