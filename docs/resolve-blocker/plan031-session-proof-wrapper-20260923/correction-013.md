# Wrapper correction 013 — sidecar ledger bootstrap and L35 census binding

**Plan-only revision responding to all four findings in the independent Correction012 review.** It preserves the user's explicit logical boundary: each exact outer execution session is one H job; Main-started roots are tracked; descendants of a launched process remain in that process-tree job until known descendants retire. `B+max(1,H)≤8` bounds registered logical roots only, not kernel TIDs, hidden wrapper threads, cgroup tasks, or machine load. This proposal itself authorizes no code change, import, fixture, probe, test, diagnostic, aggregate, admission, or launch.

## 1. Compatible ledger location and bootstrap

For target result directory `R/diagnostic-049-NNN` or `R/aggregate-049-NNN`, the ledger is a sidecar in the already existing Plan049 run directory `R`, **not** inside the target result directory: `R/.job-ledger-diagnostic-049-NNN.jsonl` with lock file `R/.job-ledger-diagnostic-049-NNN.lock` (aggregate uses its corresponding name). The target result directory remains absent until capture performs its existing exclusive `mkdir`. Fresh preflight independently proves the target directory and both sidecar names vacant, validates the strict increasing/high-water index, and binds all three exact paths in the Main admission. Sidecars remain historical after retirement and are never reused; their bytes count against the artifact cap.

Main creates the initial sidecar outside the result directory using the existing direct workspace file-edit capability, which starts no test/diagnostic/aggregate process and is not an `exec_command` execution session under the user-approved logical-job boundary. It writes a checksummed `attempt-open` record and an H=`reserved` record before calling the target `exec_command`. If exclusive creation or readback is uncertain, the target launch is not invoked. The initial H record names the intended attempt and launch phase, but has no session identity until the tool returns. Immediately after return Main binds the **exact returned session handle**, exact command and returned terminal outcome to that existing H record and reads it back. Tool polling uses that same handle and changes no root count. Missing/ambiguous handle or terminal return leaves H unresolved and prevents any new launch. The original Main/tool transcript is the accepted finite terminal boundary; it is also retained as C1 evidence.

Only `exec_command` invocations that run admitted attempt payloads are H execution roots under this boundary. Read-only preflight/control commands remain serialized one at a time; their exact transcript/terminal results are retained in status and they have fully returned before the attempt reservation is made. No second execution session is active when the attempt H reservation is created. If implementation later needs a concurrent control process or observer, it is a separately reserved root before it starts; no such helper is currently authorized.

The driver receives the exact ledger path in its Main-created immutable admission/environment, verifies the attempt/path/source hash and existing sidecar record, and passes that same absolute path to capture. Capture's `Popen` runner reserves one B root under the sidecar's cross-process `flock` before Popen, atomically reading reserved/live/unresolved roots and rechecking `B+max(1,H)≤8`. Each ledger transition is a length-delimited checksummed record, fsynced and read back under lock. Capture binds the retained `Popen` handle and identity immediately after return. A definite creation failure may close the reservation only when that exact result proves no child exists; ambiguity stays unresolved. The sidecar's ledger path does not pre-create or modify the exclusive result directory.

Every reviewed direct Main process/thread root start uses the same serialized reserve → create → bind → wait/join → descendant-retirement sequence. Hold the lock for state transitions only, never over waits. The source map must identify actual creator process/thread context, root, role, handle and terminal method. The shared fixture launcher uses authenticated process-context metadata from this attempt ledger; unknown context fails before launch. No role is inferred from event/function name. Failure to provide cross-process exclusive locking, append durability, checksummed readback or phase/path vacancy blocks the attempt; no fallback to process-local arithmetic.

## 2. L35 identity, pidfd and creator-to-owner handoff

Preserve L35's existing worker marker format (`str(child_pid)`), worker code, Consumer protocol, assertions, selectors, and every behavioral deadline. The worker's existing `fixture_process_launch` registers the child in its local invocation records. Before release, the main test-runner process reads the marker and calls the existing `record_census(session, extra=(worker.pid, child_pid))` while both worker and child are live. The accepted census row is the authoritative identity observation: it must show the same boot ID, PID, start ticks and PGID as the retained worker/child lineage, and the parent chain must connect child → worker → registered root. The child PID must be present in that exact successful census. The new shared-ledger integration durably records this full descendant identity, attaches it to the existing worker root, and reads back the acknowledgment **before** Main writes the existing release marker. Thus no marker-format change or extra worker round trip is needed.

Still before release and while the identity remains live, the main test-runner process opens a Linux pidfd for `child_pid`, then immediately rereads `/proc/<pid>/stat` and confirms boot ID, PID, start ticks and PGID match the census row. It retains that pidfd across worker exit. A pollable pidfd readiness event for that identity witnesses terminal state after reparenting; pair it with exact retained identity and ledger closure. The leader's `Popen.wait`, pid disappearance, Consumer acknowledgment, and `owned_workload` ancestry snapshot alone do not close the descendant. The implementation must close the pidfd on every success/failure path and include no-helper/no-thread descriptor ownership.

If the child exits before census/ledger acknowledgment/pidfd acquisition, if identity or ancestry differs, if pidfd open/reconciliation races, or if readback/terminal readiness is missing, retain the root as unresolved and fail the gate. Do not write the release marker on a failed handoff; preserve existing worker cleanup behavior and original deadline. If the existing scenario necessarily reaches its deadline before the acknowledgment/pidfd sequence can complete, stop and report incompatibility rather than lengthening that deadline. Linux pidfd support and the actual test-runner permissions remain unverified until implementation and separately authorized focused validation.

## 3. General process-tree retirement

The process creating a child first retains the exact returned handle, obtains full live identity, and commits the descendant attachment/readback in the shared ledger while the parent root is still live. This transaction must be inside or immediately around the existing creation wrapper so registration failure cannot release ownership or let the parent exit unrecorded. If a child exits before identity is obtained, do not assume failure or retirement: reconcile it through its matching retained wait handle plus complete census/ledger history; absent proof leaves the root unresolved. Parent release/join requires all creation intents reconciled and all known descendants terminal. A reparented non-child requires its retained pidfd witness; an ordinary child uses its exact matching wait. A process root is retired only after its own exact terminal and empty closed descendant set. Threads started by a Main process are independently tracked handles; internal threads created by process descendants stay in their root and are not claimed as individual OS tasks.

The ledger is the serialized cross-process root/descendant state; existing `INVOCATION` registries and censuses provide identity/lineage inputs only. The ledger must distinguish terminal observation for an exact descendant from a process-tree assertion. Any malformed log, lost lock semantics, unbound creator, unacknowledged child identity, unknown descendant, or uncertain terminal keeps the corresponding root charged/unresolved, disallowing aggregate acceptance.
