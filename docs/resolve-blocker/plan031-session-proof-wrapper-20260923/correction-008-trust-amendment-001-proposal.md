The original [session-proof authorization](../plan031-progress-20260922/authorization-049-session-proof-001.md) remains in force.

This proposal recommends the already accepted three choices as one scoped amendment to [Correction008](../plan031-progress-20260922/plan049-correction-008.md) §§1, 3–4. It replaces **only** the unobservable paired Main monotonic stamp/physical-time inference with ordered UTC observations, the independent durable/exclusive Main-return escrow claim with the exact visible Main/tool return as finite terminal trust boundary plus verified file copies, and an OS-task/wrapper census with the already selected logical job model. It does not weaken the driver's exclusive/durable ledger, its local identity rechecks, returned-handle ownership, current source/authority/output verification, or any resource, deadline, assertion, selector, order or error-precedence rule. UTC order annotates causally sequenced tool calls; it neither proves elapsed real time nor changes any internal W/C or scenario deadline. A backward/invalid UTC observation fails the proof rather than being relabeled as monotonic evidence. Tool `wall_time_seconds` is metadata, not tree CPU time or a behavioral clock.

Correction008/v1's requirement for exclusive/fsynced Main event files cannot be represented as independent attestation by the exposed `apply_patch` result; [wrapper validation](validation.md) lines 5–12 expressly failed that claim. Under this proposed trust boundary, Main's original visible nested tool call/result is the source of truth; an on-disk event is a checked copy, never an independently attested return. A missing, inconsistent or unreadable copy stops admission. Main may use the already allowed serial evidence/control operations to read back a copy; each outer `exec_command` used for readback is an H logical job from invocation to its exact terminal and must fit `B+max(1,H)≤8`. This adds no resident observer, writer, wrapper or helper and no new source path. It does not claim host-kernel process/task census or withstand a compromised Main/tool transcript. If an implementation needs a new concurrent helper, writer, thread or process, or cannot verify the copy and account for an existing control command, this amendment is insufficient and the attempt stops for separate authorization.

## Versioned, executable proof contract

Keep all historical v1 files immutable. For **new** current Plan049 attempts, require `plan049-session-tool-event/v2` with exact top-level keys `{schema,kind,index,ordinal,role,tool,arguments,result,started,returned,output_sha256}`. `started` and `returned` each have exactly `{utc}`: an actual Main UTC observation immediately before and immediately after awaiting that specific nested tool call, serialized as a timezone-aware UTC ISO string. Require parseable UTC, `started<=returned` and previous `returned<=next started`; ordinal continuity and the actual sequential tool-call order supply causal order. No `monotonic` key, synthetic bracket, inferred clock reading or physical-time claim is accepted. The selected roles and tool/argument/result grammar remain start, structured start-frame/readiness, zero or more readiness empty polls, then exactly `pre_admission` and `at_admission` empty polls; the latter two must affirmatively return the same live exact handle. Every poll yield remains `1..60,000` ms for responsiveness only. Preserve the exact start shell command/arguments, complete bootstrap and readiness lines, verbatim result object and UTF-8 output hash, including CR/LF; reject truncation, duplicate/conflicting readiness, non-null terminal code, tool error or uncertain liveness. Do not infer liveness from empty output.

Require `plan049-session-proof/v2`, `proof_mode=session-bound/v2`, and the existing v1 proof field set **plus** strict file records `plan054` and `evidence_amendment`; retain `admission_handoff={session_id:<exact handle>,chars:"ADMIT\n"}` and `cross_namespace_kernel_verified=false`. `user_authorization` and `correction` remain the exact original authorization and Correction008 records; the new fields bind the exact reviewed Plan054 and adopted amendment bytes without replacing or reordering the old authority chain. Proof `tool_events` references exactly the read-back v2 start/readiness/poll copies. The admission binding set and prospective note bindings append these two authority records and the v2 proof record; all previously required fields/ordered corrections and addenda remain intact. Driver validation rejects v1 for new attempts once v2 is adopted, rejects mixed versions and unknown/extra fields, and rehashes every record at both admission and immediate pre-exec. Earlier v1 outcomes are not retroactively upgraded.

Main's capture sequence is executable and noncircular:

1. Fresh source/authority/artifact/ownership/capacity/output/high-water/vacancy prechecks occur before launching the sole driver. At **the actual `exec_command` return**, Main retains the complete native result object and its exact positive, ≤16,384-digit `session_id` in the visible Main transcript **before any admission, start-frame construction or later poll**. This handle is an opaque tool handle, never a PID. If absent, terminal, ambiguous or lost, no admission follows. The target H job is charged from invocation; the launched driver's descendants belong to that launched process job, not new outer sessions.
2. Main saves a value-preserving v2 copy of that actual start arguments/result and its observed UTC pair at the vacant indexed event path, reads it back, checks exact JSON value/UTF-8 output hash/file `{path,bytes,sha256}` against the original returned object, and records the copy as secondary evidence. No success is inferred from a write tool's empty result. If write, readback or equality is uncertain, retain the target handle/charge and stop/retire by the exact same handle without `ADMIT`. It then sends the existing structured start frame through `write_stdin` **to that retained handle**, not a value reconstructed from a file. Each returned readiness/poll object gets the same original-object/copy/readback check before being used.
3. Main verifies the one complete bootstrap and readiness line, immutable request, current source/authority bytes and `pre_admission` poll. It performs the final `at_admission` live poll using the exact same handle. Between that poll and `ADMIT`, only the required copy readback, proof/admission preparation/readback and fresh checks occur. Any control readback `exec_command` is serially reserved/retired as H, with the still-live target H retained. The final proof contains the original handle, ordered event records, exact readiness/request/driver/admission path and both authority records. Admission remains exclusively created/read back as already required, and must bind the exact proof and unchanged source/identity/resource fields. An interruption or drift retires the attempt without admission; no numerical expiry is invented.
4. Main sends exactly `ADMIT\n` with `write_stdin(session_id=<retained exact handle>)` once. The driver must still wait for this explicit input; a preexisting admission never bypasses it. The driver compares the start event in the proof with its received structured start frame and local ledger's main-handle entry, then performs its original root/thread/full-ancestry checks before note publication and immediately before exec. Main preserves the actual send arguments/result, subsequent same-handle polls and the actual **outer terminal** result as visible transcript entries plus checked copies. A terminal result is bound to the `write_stdin` argument handle and earlier live sequence; if it contains a `session_id`, that value must match. An inner receipt or separate-shell PID is no substitute. A lost/ambiguous send or terminal leaves the H job/attempt unresolved and bars duplicate admission or reuse.
5. Independent runtime review checks the original visible tool-call/result objects against read-back file copies, proof, admission, send, outer terminal, driver exec-start, capture receipt and owned retirement. The terminal transcript is the finite trust boundary: do not require a new tool call that archives its own return, and do not claim an on-disk terminal copy alone proves terminality. Unknown copy/terminal/retirement facts remain unknown. No v2 proof may be built solely from files or fabricated test objects for live acceptance.

The logical resource rule remains `B+max(1,H)≤8` at **every** transition, including H=0 reserve, with all existing serial CPU-only restrictions. Each outer `exec_command` is one H logical root from invocation through exact terminal, even if it is a read-only preflight/control call; the target session remains charged while such a control call runs. Main-started independently tracked threads are H roots as already reviewed. Each launched process root is B, and its registered descendants remain grouped under that exact process job, with exact `Popen`/pidfd/native handle ownership and the reviewed terminal/ack/replay conditions. A child is not double-charged merely for being a descendant, but the root cannot retire while any known descendant is live or ambiguous. Unknown creation, fork/group escape, reuse or lost handle keeps the root charged and blocks acceptance; this is logical-job accounting, not a host task-count claim. [Correction014](correction-014.md) and its [cumulative review](correction-014-source-scope-review-002.md) supply the already reviewed job interpretation; later ninth-path authority remains as recorded in wrapper status line 35.
