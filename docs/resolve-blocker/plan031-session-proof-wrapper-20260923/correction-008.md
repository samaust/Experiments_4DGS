# Wrapper correction 008 — gated transient-service probe, execution blocked

**Plan-only revision of [correction007](correction-007.md), independently reviewed at SHA-256 `476cd545d52d7503ab853aa56bb94924c2639a4b71bc839cb97ac76929c9f475` in [its review](correction-007-independent-review.md).** This specifies phase barriers, charge, retention and cleanup. It does not launch a service, probe a cgroup, edit source/tests or clear C1–C4. The current exposed tools have **not** identified a complete first-creation-to-retirement enforcement/accounting facility for the `systemd-run` client, tool wrappers and observer calls outside the transient service. **Therefore this probe is presently unsafe and must not be launched.** The protocol below is conditional design for review if that facility becomes available.

## Fixed protocol and live evidence barriers

Use only the fresh exact positive/fork/thread service names and `--user --property=Type=exec --property=TasksAccounting=yes --property=TasksMax=8|1 --pipe --wait` candidate from Correction007; no `--scope`, `--remain-after-exit`, direct cgroup write or post-spawn migration. The service working directory, fixed minimal environment, Python interpreter/hash, `/bin/bash` client shell with `login:false`, `tty:false`, exact tool workdir `/tmp`, full `exec_command` arguments, output budget and final expanded argv must be pinned and saved before any start. The client's `/tmp` does not establish the service cwd: pin `--property=WorkingDirectory=/tmp` and a minimal fixed environment via reviewed systemd properties or stop if the host rejects them. The unit name and `ControlGroup` must be canonical, unique and vacant before start. Service messages are one LF-terminated compact JSON object with exact keys `{phase,unit,pid,cgroup,detail}`; no prose/escaped Python `repr` comparison. `detail` is a phase-specific exact JSON object. Combined `systemd-run` informational output is retained separately and cannot masquerade as a service marker. Accumulate fragmented output from the **same** original tool handle until a complete unique line; a 1,000ms first return with a live handle but no full READY is not failure. No handle, closed stdin, terminal-before-READY, duplicate/conflicting marker, actual truncation or unknown extra bytes is failure. Every empty poll and input send stays on that same handle and has yield≤60,000ms; no operational time ceiling is added.

The positive service program is a single manager-started Python process with this **state machine**, one line of stdin per transition: `READY` (print own PID/cgroup/TIDs; block) → `PING\n` → `PONG` (echo exact JSON string `"PING"`; block) → `FINISH\n` → `FINISHING` → exit0. Main first obtains a complete READY and a **baseline** unit/cgroup/task snapshot while service remains blocked. It then performs an empty same-handle live poll, sends PING on that handle, requires PONG and a **live** same-handle poll while the service is still blocked, then takes a **final live** snapshot before FINISH. Only then send FINISH and collect the actual outer terminal result. This proves post-I/O continued usability if the tool route supports it; a terminal poll before FINISH fails. The service program must reject unexpected input and EOF with a structured error, hold no background task, and emit exactly one marker per phase. A separately reviewed executable/inline `python3 -u -c` program with exact bytes and exception handling is required before any probe; Correction007's immediate-exit command is superseded and must not be run.

Each negative service uses `TasksMax=1` and also **blocks in READY before attempting** fork or thread creation. Main records baseline `TasksMax`, `TasksCurrent`, `pids.max=1`, `pids.current`, `pids.events`, full member TIDs and tool handle **while the unit is live**. On exact `ATTEMPT\n` input, it performs **one** `os.fork()` or `threading.Thread.start()`. It catches and reports a compact `ATTEMPT_RESULT` with exact `{operation,outcome,exception_class,errno,message,created_identity,retired}`; a cap-denied fork must report `OSError` with a recorded errno, and a thread start failure must report its actual class/message, not a guessed errno. Main then reads a **post-attempt live** unit/cgroup snapshot and pids event delta while the service remains blocked. Require the same unit/root, an increment in that unit's max event attributable to the single attempted creation, no unexplained task, and the typed rejection. A denial from another error or no max event does not prove the cap. If creation unexpectedly succeeds, the parent retains the child's PID/start identity and calls `waitpid` after the child exits; a successful thread is joined. It reports that owned retirement in `ATTEMPT_RESULT`, stays blocked for the post-attempt snapshot, and the control **fails** even if cleanup succeeds. Reserve this one extra child/thread in the prelaunch peak budget, so a broken cap does not itself exceed Plan049's eight-task rule. After the snapshot Main sends `FINISH\n`, the service prints FINISHING and exits with a fixed nonzero code for a correctly rejected attempt or a different fixed nonzero code for unexpected success; save the actual `systemd-run` client/outer terminal, not a synthetic success interpretation. No negative service starts until the previous unit and its client/wrappers are fully retired.

The live observer command is pinned as `systemctl --user show --property=Id,MainPID,ControlGroup,TasksCurrent,TasksMax,ActiveState,SubState,Result <exact-unit>` with a reviewed fixed shell/login/TTY/workdir and output cap. Validate the returned unit ID and canonical ControlGroup before reading **only** `/sys/fs/cgroup/<ControlGroup>/{pids.max,pids.current,pids.events,cgroup.procs,cgroup.threads,cgroup.events}` in a second, serialized, read-only observer call whose exact argv and tool result are saved. Record both observers' own process/thread identities and any tool wrappers as H during their entire lifetime. A service self-reported PID must match manager MainPID only in a verified shared PID namespace; otherwise require an exact host mapping, never numeric equality by guess. Baseline, post-PING/post-attempt and final live snapshots occur while the service is deliberately held. A unit that disappears before a required snapshot fails the probe; a later absent cgroup after documented terminal may be an expected unload, not proof that no zombie exists.

## Prelaunch resource reservation: required but presently unavailable

For the table, `B` counts all in-unit service threads, including an **unexpectedly successful** child/thread until wait/join. `H` counts every per-attempt task outside that service: `systemd-run` control client, `exec_command` shell/transport wrappers, `systemctl` observer, cgroup-file reader and their tool wrappers, plus any per-attempt manager helper. Preexisting shared user/system manager infrastructure is recorded as a baseline and excluded **only if** it demonstrably predates this attempt and creates no per-attempt task; new helpers are never declared exempt. Observer calls are serialized, but their own startup/retirement may overlap the held service/client. The proposed slot budget below is a **required enforced maximum**, not an observed host fact:

| Phase | B max | H components that must be bounded before launch | H max | Required charge |
| --- | ---: | --- | ---: | ---: |
| Client/service creation and READY | 1 | client 1 + all shell/transport/manager helpers ≤3 | 4 | ≤5 |
| Held baseline/PONG/final observation | 1 | same client/wrappers ≤4 + one serialized observer chain ≤2 | 6 | ≤7 |
| Negative ATTEMPT, even if cap fails | 2 | client/wrappers ≤4; no observer concurrently | 4 | ≤6 |
| Negative post-attempt observation | 1 after proved wait/join; otherwise 2 | client/wrappers ≤4 + observer chain ≤2 | 6 | ≤7 if B1; ≤8 if B2 |
| FINISH, outer terminal and cleanup observation | 1 until exit, then 0 | client/wrappers ≤4 + one cleanup observer chain ≤2 | 6 | ≤7 while B1; ≤6 after B0 |

At every transition enforce **both** kernel `TasksMax` for the in-unit service and Plan049 `B+max(1,H)≤8`; when H=0 require B≤7. The values “client 1,” “wrapper ≤3” and “observer chain ≤2” are **unproved reservations**, not permission to assume those counts. A qualifying host facility must identify and hard-bound each per-attempt outside task **before its creation**, continuously account for transient threads across namespaces, and prove all such tasks retired. The existing broad VTE cgroup (`pids.current=131`, `pids.max=143286`) and sampled `systemctl` output cannot do this. No complete facility has been identified. Accordingly **the prelaunch table cannot be certified; stop before the first systemd-run command or observer launch**. If a host facility later supplies a different exact H bound, rewrite and independently review this table before execution. A passing in-unit TasksMax test alone never clears external H or a future two-session writer+driver peak.

## Unit retention, partial start and cleanup order

All required snapshots are taken **before FINISH**, while the service is live. Do not use `--remain-after-exit`: with `--wait` its deactivation semantics are unproved here. After FINISH, save the original tool send/terminal response under the user's accepted finite Main/tool transcript boundary. The successful transient unit may unload immediately; absence is acceptable only if its earlier exact ID/MainPID/ControlGroup, service terminal and client wait result are all bound, known task identities have terminal/reap evidence, and a final read-only manager query finds no active exact unit. A failed transient unit may remain loaded; save failure properties and cgroup evidence **before** clearing failed state. `populated=0` is evidence of no live cgroup member, not proof that zombies were reaped.

For every start/send/query error, first freeze the exact requested unit name, original tool handle (if any), command and partial outputs. Query `systemctl --user show --property=Id,MainPID,ControlGroup,ActiveState,SubState,Result <exact-unit>` through the reviewed read-only observer facility; if the initial sandbox command may have created a unit, do **not** replay `systemd-run` merely because it returned a permission error. An in-progress approval is awaited, not retried. If identity is unknown, stop with ownership unresolved. If the exact unit is live, use the saved handle for a cooperative FINISH **only if** stdin association is affirmatively intact; otherwise, after exact unit/ControlGroup/MainPID verification, the bounded cleanup command is `systemctl --user stop <exact-unit>`. Wait for and save the original client tool terminal if reachable, then requery the same unit and task identities. If failed state persists, save it and use `systemctl --user reset-failed <exact-unit>` **only after** terminal/reap evidence is captured. Final query must show no active exact unit, no live tracked TID and either a canonical empty group or a documented manager-unloaded path; unresolved zombies/children keep the index/unit occupied. Never stop a broad slice, kill by a guessed PID, reuse a partial name or erase records. All stop/reset/query clients and wrappers consume H while running; the service may still be alive, so the table's cleanup bound must include them before those commands are allowed. If that bound is unavailable, stop and report the unresolved unit rather than performing an unaccounted cleanup action.

Before any actual probe, a distinct reviewer must accept an **exact expanded command/argv and source-byte package** for the held positive/fork/thread programs, unit names, markers, observer/read commands, environment, table bounds, facility identity mapping and failure/cleanup states. The original runner/capture argv/STDIN, CPU-only scope, all behavioral W/C/protocol/scenario deadlines, 150GiB artifacts, 64MiB memo, two same-handle driver polls, ADMIT/outer terminal and no operational time ceiling remain unchanged. A successful future probe would only establish a narrow platform capability; it would not adopt v2, satisfy C1–C4 or clear diagnostic008. **No probe, service-manager action, cgroup operation, import, test, source edit or runtime launch was performed for this addendum.**
