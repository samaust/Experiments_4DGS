# Wrapper correction 014 — in-session ledger bootstrap and exact source-scope extension

**Plan-only response to Correction013's independent NEEDS_REVISION findings.** The user-authorized unit remains `registered-process-tree-job/v1`: every exact outer `exec_command` session counts as one logical H job from invocation through terminal return; each main-started process/thread root is tracked; descendants remain grouped in the launched root until all known descendants retire. Hidden wrapper/TID multiplicity inside a logical session/root is deliberately not bounded. `B+max(1,H)≤8` is a logical-root rule, not a kernel/cgroup/machine-load limit. This proposal authorizes no source edit, test, fixture, import, probe, diagnostic, aggregate, or launch.

## 1. Bootstrap with no unverified pre-launch writer

Count **every** `exec_command` session, including read-only preflight/control commands, as one H root from invocation until its exact returned tool result/handle is terminal. Run those commands serially; the prior H must be terminal before the next starts. Store their exact command, handle when returned, terminal output and ordered UTC observations in the Main transcript/status. A lost or ambiguous result remains unresolved; never exempt a command because of its label. `apply_patch` calls that perform documentation/source edits start no admitted execution payload and do not create B/H execution roots under the user's selected job boundary.

For the actual attempt, Main's invocation of the exact target `exec_command` reserves one H slot in Main's live logical ledger **at invocation time** (the outer tool transcript is the accepted trust boundary; no pre-launch file write is claimed). Until the exact result returns, H stays live/reserved. The attempt driver is the first process in this already-counted H root; before it creates capture or any other child, it creates a sidecar ledger with OS exclusive-create semantics (`O_CREAT|O_EXCL`, mode restricted to the attempt owner), writes the initial `attempt-open` and H=1 record, calls file and parent-directory `fsync`, rereads/verifies the bytes/checksum, and acquires the sidecar lock. The sidecar is `R/.job-ledger-<kind>-049-NNN.jsonl` with `R/.job-ledger-<kind>-049-NNN.lock`; the output directory `R/<kind>-049-NNN` remains vacant for capture's existing exclusive `mkdir`. If the sidecar, lock, exact source binding, or readback is occupied, partial, unsupported, or ambiguous, driver exits before child creation; Main records the target H terminal on the exact same tool handle. An interrupted/unknown driver remains charged as H unresolved.

No second execution session may overlap this attempt. Capture receives the exact predeclared sidecar path and admission binding. It reserves B for the runner atomically under the sidecar `flock`, includes the live H=1 record in `B+max(1,H)≤8`, and binds its returned `Popen` handle. All later direct roots use the same reserve/create/bind/wait-or-join/tree-retire sequence. The lock covers only ledger transactions, not waits. A creation/identity/terminal ambiguity stays charged. Main binds the exact target session handle and actual terminal return to the H entry in the Main transcript and durable attempt report; only the exact returned same handle can retire it. If the session handle is lost, stop further execution launches and record the blocker; do not infer terminal from PID, process-table absence, or a different session.

The result directory remains absent until capture's existing exclusive create. Fresh preflight proves the exact result and sidecar paths vacant, path/index/high-water rules, and total artifact headroom. Sidecars remain immutable historical attempt evidence, never reused, and count toward 150 GiB. Driver-created initial H records are not pretended to exist before the outer execution call: the Main transcript accounts for the H reservation at invocation; the driver sidecar is created as the first operation inside that same H root before it can start B or other roots. Thus no extra bootstrap process or unverified editor write is introduced.

## 3. L35 and general tree ownership retained

Preserve the PID-only ready marker, worker string, existing `record_census(session, extra=(worker.pid, child_pid))`, Consumer protocol, test result/assertions and deadlines. While both processes are live, the test-runner main process binds the observed child's boot/PID/start/PGID and worker→child ancestry from that exact successful census into the shared sidecar, verifies durable readback, then opens the pidfd and immediately rechecks `/proc/<pid>/stat` against the census. Only then may the unchanged release marker be written. Main retains that pidfd through worker exit and closes the descendant only after a matching readiness event plus ledger/identity reconciliation. Any race or failed transition leaves the process-tree root unresolved. No polling interval or observation can extend the existing 2-second action/1-second safety-retirement behavior.

At every other process start, record the returned handle and complete identity in the shared ledger before the creator can exit. A root's matching wait/join is insufficient while its descendant list is nonempty. Known direct children close only with matching wait; reparented descendants require a pidfd opened and identity-bound while live; unknown, unrecorded or ambiguous descendants keep the root charged and block successful aggregate acceptance. Existing process-local registries/censuses provide identity evidence, not shared root accounting. No helpers, observers, threads or extra scenarios are added.
