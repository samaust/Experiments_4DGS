## Writer bootstrap and exact acknowledgments

Remove the READY nonce. The writer may emit exactly one `READY2 <kind> <index>\n` line through its **actual writer tool session**, with no other startup output, echo or second readiness line. The marker is bound by the saved writer `exec_command` result, exact session handle, kind/index, reviewed fixed command/source hash and later start record. It is not cryptographic freshness or an identity attestation; the exclusive fresh attempt path and unique actual tool handle supply only Main-trusted correlation. If either cannot be established, no driver starts.

The startup sequence is `READY2 → S2,R2(raw) → C2,R2(start) → driver exec`. `S2` carries Correction004's losslessly serialized **original writer launch arguments/result/handle** and exclusively creates `R/main-writer-049-<kind>-NNN-launch-raw.json`. `R2(raw)` acknowledges only that file: fixed path, exact byte count/SHA-256 and the entire reopened readback bytes. Main compares every byte with its original S2 payload, then strictly compares the decoded native launch result/handle to the original return. It does **not** treat this acknowledgment as evidence that a generated `start.json` exists.

New control opcode `C2` has exact JSON payload `{schema,kind,index,writer_session_id,launch_raw,ready_line}`, where `schema` is `plan049-writer-start-command/v2`, `launch_raw` is the strict S2 file record and `ready_line` is the exact `READY2` line without its LF. `C2` has the same 16,384-byte payload/22,000-byte complete ASCII frame limits and monotone sequence/header rules as Correction004; its fixed path token is `writer-start`. The writer reopens and rehashes S2, checks its own launch result/handle and sole READY line, samples its self identity/threads/transport, and exclusively writes/fsyncs/reads back `R/main-writer-049-<kind>-NNN-start.json`. That generated file has exact top-level keys `{schema,kind,index,writer_session_id,launch_raw,ready_line,writer_source,writer_identity,transport_identity,threads,observed_utc}` and schema `plan049-writer-start/v2`; nested identity shapes require a later source review and cannot imply continuous accounting. `R2(start)` acknowledges **this generated file**, carrying fixed path, count/hash and all reopened bytes. Main parses them with duplicate-key/nonfinite rejection, checks the strict record, exact S2/READY/handle/source correlations and recorded thread identities. Main cannot byte-compare generated identity bytes to a preexisting Main payload; this is self-report plus writer readback, not unforgeable observation. **Start is fully bound only after both independent R2 transitions succeed and the exact S2 and C2 records correlate.** Any missing, duplicated, partial, truncated or mismatched acknowledgment retires the candidate and prevents driver launch. The writer may not create start automatically in S2.

Correction004's state grammar becomes `READY2 → S2,R2(raw) → C2,R2(start) → (E2,R2 → T2,R2)+ → I2,R2 → P2,R2 → A2,R2 → F2,writer-terminal`. Sequence numbers continue across **all** frames with one outstanding frame and no resend after ambiguous delivery. The final `I2` payload renames `next_op` to `terminal_action` with exact literal `"F2"`: it identifies the **future terminal action after P2 and A2**, not the next accepted operation. The I2 file binds the last event and writer charge as before; it asserts only intent. `F2` now has exact JSON payload `{schema,kind,index,exit_intent}` with schema `plan049-writer-finish/v2` and a strict record/hash of the I2 file; its fixed path token is `writer-finish` (no output file). The writer accepts F2 only after verified P2/A2 and equality to the saved I2 record, performs **no** further file write, then exits. Main requires the actual F2 `write_stdin` call to use the writer handle and return unambiguous terminal exit0 before any `ADMIT\n`. No R2 is expected for F2. This supersedes Correction004's empty F payload; proof/admission still bind I2, never the future terminal return.

## Two-stage index gate

**Before writer launch**, Main computes each kind's high-water index across every Correction004 registered family, including retired/partial/legacy records, and chooses `i` strictly greater than that high-water. It requires **all** fixed paths for `i` vacant, including the two bootstrap paths, all future writer/raw/event/proof/admission/driver/Main/log/directory paths and unclassified indexed names. This is a fresh-index selection observation, not an exclusive reservation; a race before S2 is possible and is resolved only by exclusive creation and a new recheck. No path is deleted, renamed or silently reused.

**Immediately before driver entry**, rerun the all-family scan. The only permitted occupied paths at `i` are the exact two bootstrap files `main-writer-049-<kind>-NNN-launch-raw.json` and `main-writer-049-<kind>-NNN-start.json`, with the exact previously acknowledged bytes/hashes and current writer session correlation. Every other path for `i` must still be vacant, including `launch-identity`, admission, note, driver outputs, directory, events/raw escrows, proof, writer intent/failure/journal/archive and Main launch records. No other occupied or retired index may be **higher** than `i`; any competing occupancy at `i`, higher index, unreadable legacy record or unclassified indexed name stops the driver. Existing lower retired indices remain historical. This is a narrow same-attempt bootstrap allowlist, not a bypass of the driver's high-water rule: a later authorized source change would need to implement separate pre-writer and driver-entry gates and preserve rejection of all competing/future occupancy. The concrete registered parser table for all Main legacy/journal/failure names must be independently reviewed before implementation; until then any ambiguous name blocks. C4 still needs fresh source/authority/storage/process/thread/CPU-only checks at the actual launch boundary.
