## Prior findings and disposition

1. **Lifetime, capacity and ownership: honestly blocked.** Correction004, “Continuous charge and terminal archive: present infeasibility,” explicitly distinguishes writer samples from continuous accounting, includes otherwise invisible shell/PTY/transport processes, rejects a guessed H=1, and states that no sufficient facility has been identified. This addresses the prior review's concern without pretending that the writer's own observations prove its full live footprint. Its startup command/no-child/no-thread statements are requirements for a possible future implementation, not established platform facts. The unchanged Plan049 §§1, 4.2 and Correction008 §§1, 4 still prohibit an unexplained extra process/topology and require complete resource/retirement accounting. The conclusion that this proposal cannot clear a driver launch on the currently established facilities is justified. It is a capability finding for this design, not a proof that every conceivable compliant platform implementation is impossible. No new probe was needed or performed to repeat that limitation.

2. **Retirement and hash chronology: acyclic in intent; one field is inconsistent with the state sequence.** The stated order E → T → I → P → A → F → actual writer exit → ADMIT keeps actual retirement outside immutable proof/admission, with no retroactive terminal hash. Admission remains the writer's last write and H=0 remains prospective until Main observes retirement. This preserves Correction003's chronology fix. However, the exact I payload says `next_op:"FINISH"` even though the next accepted operation is P, followed by A and then wire opcode F2. Rename this field as a future terminal action or define it explicitly as such, and pin its mapping to F2; it cannot literally be the next protocol operation. The terminal archive still needs separate authorization and evidence, as item 6 explains. Main's observed exit and an independently proved complete retirement are distinct requirements.

3. **Native elapsed: previous resolution retained.** The addendum refers to Correction003's exact event/timing schema and does not supersede its rule: absence maps to null, valid present finite nonnegative int/float is copied by exact type/value, and malformed presence including bool is rejected. Correction004's shorter “if present and valid” wording is compatible only with that inherited reject rule, not permission to discard malformed fields. There is still no implemented v2 validator or real event evidence.

4. **Clock semantics: the authorization choice is now explicit.** “Authority and clock meaning” selects ordered UTC observations, expressly waives any claim of physical-time brackets or monotonic boundaries, acknowledges undetected forward steps, and calls for precise user approval of the weaker model. This resolves the prior ambiguity between physical bounds and observation order. The required procedure is causally coherent: Main samples before the driver call, gets E readback, samples after escrow, sends T containing that observation, finishes T readback, then starts the next driver call. T's timestamp is after the raw E escrow, not after T's own persistence; this distinction avoids a self-referential timestamp requirement. The inherited across-event inequalities must remain mandatory in an adopted validator: the addendum's “may require” should not silently weaken Correction003's “require.” Known clock problems must not be relabeled as exact timing evidence. Current Correction008 §3 still requires its v1 UTC/monotonic stamps; C2 remains unmet until a separately authorized amended criterion and actual evidence exist.

5. **Control grammar and serialization: substantial coverage added, but not decision-complete.** “Proposed one-writer control grammar” now supplies operations for event, intent, proof, admission and finish; contiguous frame sequence, one outstanding exchange, full readback, partial-output accumulation, handle correlation, no blind resend and explicit bounds are useful improvements. T carries the previously missing post-E timing/event information and validates it against the escrow. Two concrete gaps remain. First, S creates both `launch-raw.json` and an automatically generated `start.json`, but its single R2 contains only the original S payload bytes. No specified response/read operation supplies Main with the generated start record's full bytes, strict hash/length record, or its completed fsync/readback status before P must bind it. A separate startup-record readback transition or an exact explicitly defined compound response is needed; the current universal R2/original-payload equality rule cannot perform both roles. Second, the READY nonce has no specified generation, uniqueness or later binding/check rule. Either define its role and bind it, or remove it from the protocol. Exact schema literal values and nested identity/start/archive/journal record types are still not fully pinned. These are implementation-specification gaps; the text correctly calls its grammar untested and prohibits using this review as transport evidence. The inherited rejection of lossy JSON, byte limits, exclusive creation and full-byte comparisons remains necessary.

6. **Failure reconciliation and archive trust: recursion correctly exposed; acceptance boundary still unadopted.** Correction004 retains same-driver-handle ABORT/reconciliation and distinct writer cleanup from Correction003. It now explicitly identifies the terminal-archive regress: an archiver cannot persist its own eventual tool terminal return before exiting, and another archiver merely repeats that problem. Ending at a trusted Main/tool transcript or using an atomic durable-return primitive would be a real change of evidence boundary. The text correctly says that boundary has not been accepted and rejects missing/ambiguous acknowledgments, lost transcript or unresolved processes. This is an honest blocker, not a completed archival protocol. Concrete failure/archive schemas and a finite authority rule would be needed before adoption. A delayed response may still be collected on the same handle without a new operational deadline; no ambiguous exchange authorizes a resend or a new attempt.

7. **Authority, schemas and path families: authority corrected; expanded scan needs phase semantics.** The first section accurately distinguishes Correction016's current planning adoption from the runtime addenda list, which still ends at001–015 in `R/launch-049-exec.py::main` and `scripts/vipe_benchmark/s1_validation_contract.py::no_timeout_launch`. Future016/017 ordering is reserved for fresh authority review. Current `session_proof` still requires the exact 15-field v1 proof and fixed Correction008 authorization, so neither new grammar nor a 19-field v2 proof is runtime authority.

   The indexed-path paragraph usefully adds raw escrow, writer, log, directory, retired/partial and legacy Main families and fails closed on unclassified names. It is not yet an exact parser table: “all Main” records and “any versioned writer journal/partial path” still need concrete registered names and typed legacy extraction. More importantly, distinguish initial index reservation from driver-entry validation. The writer must create its launch/start records before the driver starts; an unconditional all-family rule at driver entry requiring its index to exceed every occupied index and every candidate path to be vacant would reject those same required bootstrap files. Main must select a wholly vacant fresh index before writer creation, then the reviewed driver must validate only an exact permitted set of already-created bootstrap records belonging to this attempt, while requiring all future output paths vacant and rejecting competing or retired occupancy. This is a prospective design requirement, not permission to bypass current high-water checks. No preflight or vacancy claim is made by this review.

8. **Source scope, inverse and preservation: unchanged conditional gate.** The final paragraph inherits Correction003's reviewed source boundary and inverse requirements, keeps all counts/argv/STDIN/deadlines/resources, and explicitly authorizes no source edit, import, probe or launch. There is no concrete implementation or inverse to validate. Capture/helper source can remain unchanged only if complete writer retirement before ADMIT is established under an adopted authority; the accounting blocker prevents assuming that property today. No preservation test or source-readiness result is implied.
