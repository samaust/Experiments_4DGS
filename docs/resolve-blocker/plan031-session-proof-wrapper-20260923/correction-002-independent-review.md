## Findings to resolve in the adopted design

1. **Writer lifetime and capacity are unresolved.** Correction008 §1 forbids the new process and §4/`session_proof` require `H=0` at admission. `launch-049-exec.py` lines 189–210 checks the exact `B+max(1,H)` value and then requires `H=0`; `no_timeout_launch` lines 612–615 repeats that check. The proposed writer may be a separate tool session and therefore a sibling, not a descendant of the driver. The later `creation_identity_snapshot` and `owned_workload` in `s1_helper_session.py` enumerate the capture root's descendant tree and set `H=0` (lines 519–538, 541–587); capture uses those checks before creating the runner (`s1_validation_capture.py` lines 48–64). Merely changing the admission's `H` to one would not establish continuous ownership and charge at later creation boundaries. Even if `H=1` has the same numeric reserve as `H=0`, that arithmetic coincidence does not prove the writer's identity, thread count, or retirement, and a transport child or extra thread can make `H>1`. Specify whether the writer is provably retired **before** admission and capture, with a bound terminal record and no subsequent writer-dependent write, or remains live; the latter needs a reviewed account in every later creation/census path, extending the currently named source delta to the capture/helper ownership code or another equally complete mechanism. Show the exact namespaces, identities, thread counts, ownership roots, simultaneous peaks and failure charges. Unknown ownership blocks creation.

2. **The writer-retirement record conflicts with immutable proof chronology unless its timing is fixed.** The proposal says the v2 proof/admission/note bind a writer record that proves retirement, yet the writer must remain ready through the final `at_admission` escrow and the writer appears to perform subsequent event/proof/admission evidence writes. A proof finalized before `ADMIT` cannot truthfully bind an actual future retirement. Define the last writer operation, terminate and verify it before proof construction if retirement is pre-admission, and identify the mechanism that exclusively writes/reads back the proof and admission after that retirement. If retirement is later, bind only the pre-admission writer identity/charge in the immutable proof and bind actual retirement in a subsequent terminal record; do not describe the former as proving retirement. The latter design also needs the later capacity changes in finding 1.

3. **Native elapsed has contradictory absence semantics.** Correction002 line 9 says `native_wall_time_seconds` equals the result field when present as a finite nonnegative number, “otherwise `null`,” then says an “absent/malformed native field” rejects the event. The current v1 contract neither requires nor checks `wall_time_seconds` (`session_proof` lines 497–524); historical event000 contains it, but that does not make it guaranteed by the tool interface. Choose one exact policy: absent means `null` and is accepted while present malformed values reject, or absence also rejects and `null` has no valid case. Preserve the native result object, reject bool/nonfinite/negative values if present, and compare the timing copy by exact type/value. Native elapsed is duration metadata, not a monotonic boundary or whole-tree CPU measure.

4. **UTC bounds need precise validation and wording.** Sampling before invocation and after durable escrow gives operational happens-before bounds; it does not measure the nested call start or return. A timezone-aware wall clock can step, so numeric UTC inequalities are reliable bounds only under a stated clock-stability assumption; reversed observations must fail, while a forward adjustment can widen the interval. State whether the v2 validator checks `before_call_utc <= after_escrow_utc` and `previous.after_escrow_utc <= next.before_call_utc` for the serialized call sequence, and how a detected/uncertain clock discontinuity fails closed. Do not derive a monotonic origin or exact elapsed call interval from native `wall_time_seconds`. The proposal's phrase “overlapping broad bounds” should not become permission to accept unordered event bounds: the single Main invocation should finish one escrow before sampling the next `before_call_utc`. On-disk ordinals alone cannot authenticate that actual order; independent comparison to original tool calls remains necessary.

5. **Transport/readback is still a capability requirement, not a protocol.** The proposal correctly abandons shell-argument interpolation, requires exclusive creation and accepts a fixed fail-closed size limit. It does not identify a callable private framed channel, its maximum *encoded* payload size and acknowledgment budget, how the writer avoids echo/truncation, or how Main obtains the exact on-disk bytes in the same original-return context for byte comparison. Specify a frame length/encoding, full-write/full-read and EOF rules, response correlation to attempt/ordinal/path/handle, independent local hash/readback, duplicate/partial-target handling, transport timeout/ambiguous response, and the exact source of original bytes. A digest-only acknowledgment, parsed-object equality, or a result reconstructed from a log cannot satisfy the stated original-envelope byte comparison. `JSON.stringify` itself can fail or omit non-JSON values before persistence; define the supported native object shape and reject any lossy serialization. The saved synthetic `apply_patch` Add File overwrite in `validation-addendum-001.md` confirms that path is not exclusive.

6. **Same-handle failure path is directionally correct but needs executable states.** On any failed start/poll escrow, no event/proof/admission/`ADMIT` is valid; retain the exact returned handle in the same Main invocation and compare to any previously escrowed handle. If the start call launched a driver but returned no exact handle, stop with unresolved ownership rather than guess. If an affirmative same-handle live result exists, send one `ABORT\n`, capture its actual response and outer terminal, retire both driver and writer, and retain partial files. Define how a failed/ambiguous abort response and writer death are recorded without using the failed writer as the sole evidence channel; reconcile the same handle before another attempt. A wrapper `write_stdin` result must not be confused with the driver's same-handle `write_stdin` results. This needs concrete source and original tool evidence before C1/C3 can pass.

7. **Versioned authority and cross-record equality must be specified in the implementation review.** The current `session_proof` requires the exact 15-field v1 proof, exact 11-field v1 event, fixed Correction008/authorization hashes, contiguous start/readiness/final-two roles, actual handle on every live return, exact start arguments, sole readiness output and causal v1 stamps (`s1_validation_contract.py` lines 437–528). `no_timeout_launch` requires the exact 18-key admission binding dictionary and the current ordered corrections001–015 (`s1_validation_contract.py` lines 574–615); the driver independently constructs the same admission dictionary and prospective note bindings (`launch-049-exec.py` lines 194–212). All these places must reject mixed v1/v2 records and bind the fixed adopted amendment/user authorization, writer identity record, v2 events and unique raw escrows without a proof/admission hash cycle. Clarify whether `evidence_model_correction` points to this blocker proposal or a new adopted amendment under the Plan049 run directory, with fixed path and exact hash. Preserve the existing Correction008 and authorization records and the current corrections001–015 list; Correction008's historical “001–008” list is no longer the current source list.

8. **Scope and rollback require a sharper boundary.** The named source delta excludes `s1_helper_session.py` and `s1_validation_capture.py`, although a writer alive during capture would evade their root-descendant census and `H=0` checks. Either prove pre-admission writer retirement or seek explicit source-scope review before changing those files. The inverse patch is sensible only before any accepted v2 admission; after acceptance, retain v2 history validation. Keep runner/capture argv and STDIN, 78-source membership, 249 methods/1,028 callbacks, W/C and scenario deadlines, CPU-only scope, 150GiB artifacts, 64MiB memo, `B+max(1,H)≤8`, no operational time ceiling, and actual outer terminal/retirement checks intact.

The dependency order **escrow → event → proof → admission → send/terminal evidence** is acyclic if the proof names only the future admission path and if post-send records are not inserted retroactively. The v2 proof can preserve `session-bound/v1` as the *trust mode* while changing its schema to v2; it must still say that the tool transcript is trusted Main evidence, not independent cross-namespace kernel attestation. The readiness line, two final empty same-handle live polls and driver-local root/thread/ancestry rechecks remain mandatory.
