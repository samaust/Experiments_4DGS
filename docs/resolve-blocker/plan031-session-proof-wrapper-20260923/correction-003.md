## Lifetime, identities and charge

Choose **one pre-admission writer session, retired before `ADMIT\n`**. Main starts it before the sole driver, holds its distinct tool session handle, and never treats the writer handle as the driver handle. The reviewed writer uses no subprocess or worker thread; it records its own boot ID, PID namespace identity, PID/start ticks, ancestry, exact thread list and descendants from its namespace at startup and before/after each frame. Its executable/script bytes and self-recorded identity are bound to an exclusive `main-writer-049-<kind>-NNN-start.json`. Main retains the exact original writer launch result/handle and compares it to the writer's readback of that result. The driver's independently recorded root/thread/ancestry remains separate; no cross-namespace PID equality or kernel attestation is inferred. `B` is the driver's actual stable root-thread count. While both sessions live, `H` is the conservative sum of **all** writer process/thread/descendant and transport-wrapper charges outside that driver root, never an arbitrary `1`; reserve `B+max(1,H)≤8` before driver creation and every relevant creation. A writer thread/child increase, inaccessible namespace, uncertain ownership, or unobservable simultaneous peak blocks admission. The user would need to authorize this additional trusted self-report/accounting channel; tool routing alone does not prove process identity.

After the final same-handle `at_admission` poll, the writer exclusively saves its raw escrow and event, then creates/fsyncs/readbacks an **intent-to-exit** record. That record names the single forthcoming `FINISH` action but does not claim exit. The writer then saves the v2 proof and admission, with admission as its last file write, and accepts exactly one `FINISH` frame; it closes its channel and exits. Main requires the actual writer `write_stdin` **arguments** to use the saved writer handle and its return to report unambiguous terminal exit0 before sending `ADMIT`; a terminal result need not itself repeat `session_id`. No writer, transport shell or helper may remain live when the driver enters capture. The v2 proof/admission bind only the pre-admission writer-start/charge record and intent path/hash, **not a fictional future terminal result**. The actual terminal tool return is a separate post-proof Main record correlated to the start/intent; it is archived exclusively after the driver ends. If Main loses that return before `ADMIT`, no admission. If its later durable record is lost, final acceptance fails even if the driver ran. A post-driver archival writer, if needed, runs only after the outer driver terminal and has its own charged, exclusive record; it is not a second live pre-admission writer. Main must also save the `ADMIT` send and outer terminal originals after the driver is terminal. This later archive is not inserted retroactively into proof/admission/note hashes. The exact post-run archival facility is still unverified.

At admission, the writer is gone, so the existing capture/runner/helper descendant ownership paths can retain `H=0`. The prospective amendment changes the pre-admission capacity/ownership gate only and requires proof of writer terminal exit before ADMIT; it does **not** change `s1_validation_capture.py` or `s1_helper_session.py`. If writer retirement or independence from capture cannot be proved, stop: keeping it live would require separately authorized edits to both those files and every later creation/census path. The driver still validates its original stable root/thread/ancestor identity immediately before capture exec. Its `B+max(1,H)≤8`, 150GiB storage and 64MiB memo bounds remain exact throughout.

## Frame, bytes and failure states

The proposed channel is the writer's own persistent `exec_command` session, with `tty=true` only if the reviewed writer disables echo/canonical translation before reporting ready; otherwise a verified binary-safe, non-echoing stdin channel is required. Main sends a single ASCII line per frame through `write_stdin`, distinct from every driver `write_stdin`: `E2 <kind> <index> <ordinal> <path-token> <N> <sha256> <base64>\n`. The fixed raw path named by the token is `R/main-session-049-<kind>-NNN-raw-MMM.json`; fixed writer records are `R/main-writer-049-<kind>-NNN-start.json` and `R/main-writer-049-<kind>-NNN-exit-intent.json`. `<N>` is the byte length of the **losslessly serialized JSON** payload. The payload is exactly `{schema:"plan049-raw-tool-envelope/v2",kind,index,ordinal,tool,arguments,result,session_id}`; the last value is the actual returned driver handle, equal to `result.session_id`. A reviewed pure-JS UTF-8/base64/SHA-256 implementation produces bytes from the actual returned JS objects; it must reject non-JSON values, cycles, accessor or `toJSON` transformations, nonfinite numbers, `undefined`, ill-formed surrogates, and any parse/round-trip mismatch rather than omit or coerce them. The exposed API supplies parsed objects, not original wire bytes: “raw” means the exact reversible serialization of those returned objects and exact output string, **not unknowable tool wire bytes**. Compare original objects with decoded readback at strict key/type/value depth, and compare every serialized byte; parsed-object equality alone is insufficient.

Set an initial hard limit of **16,384 payload bytes** and **22,000 complete ASCII frame bytes** including header/newline; choose no larger live limit without measured tool-input/output capability review. Set the writer call's `max_output_tokens` to at least 32,768 if supported, and reject any observed output truncation, missing field or unexplained echo. The writer reads one complete LF-terminated frame, validates ASCII grammar, exact Base64 length and canonical encoding, decoded length `N`, SHA-256, fixed path token and currently vacant target; EOF/partial/multiple frames fail. It uses `O_CREAT|O_EXCL|O_NOFOLLOW`, full-write loop, file fsync, close, directory fsync, exact reopen/readback and independent hash. Its sole `R2` acknowledgment includes the attempt/ordinal/path token, original driver handle, `N`, hash and **the full readback bytes as Base64**. Main rejects missing, duplicate, extra, truncated or ambiguous responses, decodes and byte-compares those bytes to its pre-send buffer in the same invocation, and checks the writer tool return carries the writer handle, never the driver handle. Any over-limit return is a retired attempt, not a truncated event. This is a testable protocol proposal; the `write_stdin` input size, response cap, PTY translation and durable directory semantics are **not yet proven**. If they cannot be established on a synthetic fixture without a driver, this design is infeasible on the exposed interface.

The start or any poll return is handled by these states: `RETURNED_EXACT_HANDLE` → `SERIALIZED_LOSSLESS` → `FRAME_SENT` → `EXCLUSIVE_FSYNC_READBACK_ACK` → `EVENT_SAVED`. Only the last two permit a proof event. Serialization failure, size overflow, transport failure/timeout, writer death, occupied/partial file, fsync/close/readback mismatch, ambiguous acknowledgment, invalid tool result, or output truncation enters `NO_ADMISSION`. The in-memory exact driver handle from the original return is retained across the escrow attempt and compared with any earlier escrowed handle. If the start has no exact handle, mark ownership unresolved and stop; never guess, send to a PID, or relaunch. If an exact handle exists, make one empty same-handle liveness poll if needed; if affirmatively live, send `ABORT\n` **once** to that driver handle and collect its original return/outer terminal. If abort response is absent/ambiguous, reconcile through that same handle, never repeat `ABORT` blindly or start another driver. If the writer died, record abort results in the Main transcript and archive after driver terminal through a separately reviewed exclusive channel; do not claim the failed writer persisted them. Partial paths remain occupied; index retires. The writer is separately retired/reconciled by its **writer** handle, with no driver signaling through it. Any unresolved session or archive leaves C1/C3 unmet and blocks another launch.

If `wall_time_seconds` is absent in the native result, the timing copy is exactly `null` and absence is accepted; if present it must be an exact finite nonnegative `int` or `float` (not bool), copied by exact type/value. It is elapsed metadata only. For each event require valid UTC format and `before_call_utc <= after_escrow_utc`; for sequential calls require `previous.after_escrow_utc <= next.before_call_utc`, because Main finishes one escrow before starting the next call. Reversed observations or detected/uncertain UTC clock discontinuity reject the attempt. These inequalities are valid physical-time bounds only under an independently supported clock-stability assumption. A forward clock step can hide inside a widening bracket; the present tools do **not** prove that assumption. Until a reviewed platform clock-stability facility exists, label these as ordered UTC observations, not guaranteed physical-time bounds; if the authorized acceptance requires physical bounds, **C2 remains infeasible**.
