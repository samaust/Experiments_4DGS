## Proposed one-writer control grammar

Let `R=docs/resolve-blocker/plan031-progress-20260922`; fixed attempt suffix is `<kind>-NNN`, with `NNN` at least three digits. The writer is launched before the driver with a fixed reviewed command, one tool session, no retained shell process, and no child/thread creation. The initial tool return must contain its actual positive writer handle; a missing handle is unresolved ownership and stops before the driver. The writer emits one bounded `READY2 <kind> <index> <nonce>\n` line after disabling PTY echo/translation. The **first dependent Main action** after receiving the writer launch return is lossless serialization and a `S2` frame to that same writer, escrowing `{schema:"plan049-writer-start-envelope/v2",kind,index,writer_session_id,arguments,result}` at `R/main-writer-049-<kind>-NNN-launch-raw.json`. Its decoded readback must equal the original parsed launch result and handle. The writer then publishes `R/main-writer-049-<kind>-NNN-start.json` with executable hash, self-observed boot/PID namespace/PID/start ticks/ancestry/threads and transport identity, strictly bound to that launch escrow. If this bootstrap fails, no driver call occurs. This does **not** magically make the writer's own pre-escrow memory durable; C1 is conditional on successful S2 readback.

Every writer input frame has ASCII grammar `OP2 <seq> <kind> <index> <fixed-path-token> <N> <sha256> <canonical-base64>\n`; `OP` is one of `S` (start escrow), `E` (driver tool-result escrow), `T` (v2 timing/event), `I` (exit intent), `P` (proof), `A` (admission), or `F` (finish). The only accepted state sequence is `READY2 → S,R2 → (Eordinal,R2 → Tordinal,R2)+ → I,R2 → P,R2 → A,R2 → F,terminal exit0`; event ordinals start0 and are contiguous, with the last two roles exactly `pre_admission` and `at_admission`. Sequence numbers start0 and increase by exactly1; only one frame may be outstanding. `N` is the decoded UTF-8 JSON byte length except `F`, for which `N=0`, SHA-256 is the empty-byte hash and Base64 is the literal `-`. Frame grammar fixes the full path from kind/index/ordinal/type; the path token is an identifier, never an arbitrary path or shell expansion. The `S` payload has the exact writer-start-envelope keys above; each `E` has Correction003's exact eight raw-tool-envelope keys; each `T` has Correction003's exact 11 event-v2 keys; `I` has exactly `{schema,kind,index,writer_session_id,driver_session_id,last_event,charge,next_op}` with `next_op:"FINISH"`, a strict last-event record and `charge` exactly `{B,H,total,writer_identities,transport_identities,observed_utc}`. The charge identities are full namespace/PID/start/thread records, `B` and `H` are exact nonnegative integers, and `total=B+max(1,H)≤8`; these are sampled claims, not continuous proof. `P` has Correction003's exact 19 proof-v2 keys; `A` has the current admission schema with Correction003's exact 22-key v2 bindings. The writer rejects mixed kind/index, duplicate sequence/path, unknown operation, extra keys, noncanonical Base64, payload >16,384 bytes, complete ASCII frame >22,000 bytes, mismatched length/hash, missing preceding dependency, EOF inside a frame or input after `F`. The first driver `E` payload is the actual `exec_command` arguments/result/driver handle; later `E` payloads are actual same-driver-handle empty `write_stdin` calls. `T` follows its corresponding `E` readback and carries the exact event v2, its newly sampled `after_escrow_utc`, `before_call_utc`, native elapsed copy and raw-escrow record. The writer must reject an event whose native objects/handle/output hash do not match that readback. `I` follows the final `at_admission` event and records only FINISH intent and current charge, not an exit assertion. `P` writes the v2 proof binding static authority, identity, start/intent and all event records; it names only the future admission path. `A` writes admission binding the proof. `F` is accepted exactly once after a verified `A`; it writes no further file and exits. The driver receives `ADMIT\n` only after Main observes the writer's unambiguous terminal exit0 and separately verifies the prospective `H=0` condition.

Each successful `S/E/T/I/P/A` gets exactly one `R2 <seq> <op> <path-token> <N> <sha256> <canonical-base64-readback>\n` response containing **all** bytes reopened from the exclusively created, file-fsynced, directory-fsynced path. Main decodes and byte-compares them to its original frame payload in the same invocation. The writer uses `O_CREAT|O_EXCL|O_NOFOLLOW`; existing, symlink, partial or failed targets are never reused. Main accumulates the writer's actual tool-output chunks only from the saved writer session until one complete LF-terminated R2 line is present. It uses empty input and ≤60-second yields for partial response collection, with no operational timeout. Every chunk and tool result must identify the same live writer session until `F`; if the interface omits a handle on the terminal `F` result, correlate its **call arguments** to the saved writer handle and require exit0. Reject any echo, unrelated byte, duplicate/late R2, wrong sequence/op/path/length/hash, extra line, truncated output indicator, over-budget chunk, or missing complete response; never resend a possibly received frame. A bounded `max_output_tokens` request alone proves no nontruncation, so full Base64 length/hash/readback comparison and tested transport behavior are required. A failed or ambiguous writer exchange leaves the driver unadmitted and triggers Correction003's exact-driver-handle ABORT/reconciliation states; a failed writer handle is separately retired. No `R2` from the writer counts as a driver live poll. This grammar is untested and is not a claim that `functions.exec` exposes the needed lossless channel.

## Continuous charge and terminal archive: present infeasibility

Correction003's writer self-snapshots before/after frames are **samples**, not continuous proof. A process or thread can appear and retire between samples; a writer's own report is not unforgeable independent observation, and the tool session handle is not a kernel PID or namespace map. A shell/PTY/transport wrapper may exist outside the writer's namespace or descendant tree. The exposed `exec_command`/`write_stdin` results do not supply an authenticated, continuous cross-namespace process/thread census, creation gate, or complete wrapper-retirement attestation. Charging a fixed `H=1`, even when the writer reports one thread, would silently ignore that gap. A credible implementation would need a platform facility that continuously and independently accounts for **every** writer, shell/transport wrapper, child and thread from writer startup until confirmed retirement, maps each namespace/root without PID guessing, reserves the actual simultaneous peak with the driver as `B+max(1,H)≤8`, and certifies that no such process remains before ADMIT. No such facility has been identified in the exposed tools or prior validation. **Therefore the current pre-admission-writer proposal cannot establish C3 or clear a driver launch under the unchanged capacity/ownership rule.** Self-report trust could be separately proposed to the user, but that would be a further trust change, not an unforgeable proof and not authorized here.

Post-driver archival has a second finite-proof limit. Once the pre-admission writer exits, Main retains actual writer-FINISH, ADMIT-send, abort (if any) and driver-terminal tool returns in its trusted transcript/in-memory state; none may be inserted into the immutable proof or admission. Only after the outer driver is terminal could a separately charged archival writer exclusively save/read back those results at fixed `<kind>-NNN` archival paths, with the same full-byte frame/ack rules. It can escrow **its own launch return** after startup, but it cannot escrow **its own eventual terminal return before it exits**. Launching another archiver for that return repeats the problem indefinitely. The evidence chain must end explicitly at an external trusted Main/tool transcript boundary, or use a platform atomic durable-return primitive. If acceptance requires every writer's own terminal return to be exclusively persisted by an already-retired writer, it is logically impossible by this recursive scheme. A missing/ambiguous archive acknowledgment, lost Main transcript, unresolved archive process, or mismatch fails final acceptance and blocks reuse of the index; it is not repaired by a fabricated terminal record. The current authority has not accepted this terminal trust boundary, so archival feasibility and C1/C3 remain open.
