## Four targeted findings

1. **Generated startup record readback: resolved by a separate transition.** W/Correction005, “Writer bootstrap and exact acknowledgments,” makes S2 publish only the original launch envelope and adds C2 to generate, exclusively publish, fsync and return the full start record. This provides the missing start-file byte/hash handoff before the driver starts or proof binds it. The exact generated top-level keys and schema are specified. C2's generated R2 is expressly a special case to Correction004's general original-payload byte-equality rule: Main validates the generated bytes, strict file record and S2/READY/handle/source correlations; it does not pretend those sampled identity bytes were already in its command payload. S2 and E2 still require exact lossless original-object and byte comparison. The start record transitively binds the S2 escrow, and no automatic S2 start publication remains. Nested identity types and their supported observation mechanism are explicitly deferred; this is not a complete executable schema or an independent identity proof. The reference to a C2 “record” should mean the exact retained command/tool transcript unless a later reviewed schema assigns a file; no third bootstrap file is authorized by the current two-file gate.

2. **READY nonce: resolved by removal.** The exact marker becomes `READY2 <kind> <index>` without LF in the saved `ready_line`. Its correlation rests on the actual writer tool return/handle, exact source/command, S2 and start binding. The text correctly denies cryptographic freshness or kernel attestation. This does not permit writer readiness or an R2 acknowledgment to substitute for the driver's sole readiness line or either mandatory driver live poll. The proposed channel remains untested.

3. **Intent/FINISH semantics: resolved with an explicit supersession.** The I2 field is now `terminal_action:"F2"`, meaning the future terminal action after P2/A2, so it no longer claims FINISH is the next accepted frame. The new F2 JSON payload binds the exact I2 record and replaces Correction004's zero-byte F frame. Therefore F2 must use ordinary JSON length/hash/Base64 framing; the old empty-byte hash and `-` sentinel are superseded. C2 likewise expands Correction004's opcode set and state grammar explicitly. F2 has no output file or R2, and actual terminal exit0 must be correlated to the saved writer handle through the real call arguments. This is consistent with retaining intent rather than future terminal evidence in proof/admission. The acyclic order remains S2 → C2 → E2/readback → timing sample → T2 → I2 → P2 → A2 → F2/actual exit → ADMIT → later terminal/archive evidence. No timing or file hash is backfilled into an earlier record.

4. **Index reservation versus bootstrap occupancy: resolved as a two-stage rule.** “Two-stage index gate” now requires a wholly vacant fresh index before writer launch, explicitly says that observation is not an exclusive reservation, and rechecks before driver entry. Only the two acknowledged bootstrap files may then occupy that index; all later paths must remain vacant and competing/higher/unknown occupancy fails closed. This removes the earlier self-rejection in which a new all-family driver scan would reject its own required writer records. Rechecking bytes/hashes and writer correlation prevents a generic same-index exception. All-family parser tables and typed legacy handling remain an independent pre-implementation gate. The concrete driver must apply its entry gate before its own identity/output publication and preserve exclusive subsequent writes; this proposal does not change today's driver rule. No actual vacancy, high-water index or current process ownership was established by this review.

## Inherited requirements and remaining limits

Correction005 preserves the frame sequence across all opcodes, one outstanding exchange, exact writer/driver handle separation, no resend after ambiguous delivery, fixed paths, strict duplicate-key/nonfinite handling and full readback. It adds no source edit or capability authorization. Two inherited wording points must be made unambiguous in any later concrete protocol:

- Its statement that a “partial” acknowledgment retires the candidate must distinguish an incomplete or unresolved acknowledgment from an ordinary partial output chunk. Correction004 explicitly permits bounded chunk accumulation with empty same-writer-handle polls and no operational timeout. Mere transport fragmentation is not evidence of failure; an invalid, truncated or unresolved exchange cannot advance the state machine. Read the new rule in that compatible sense, or clarify it before implementation.
- Correction003's within/across-event UTC inequalities and absent-versus-malformed native-duration rules remain required. Correction004's “may require” is not permission to drop those inequalities. Ordered observations still supply no physical-time guarantee or monotonic boundary measurements. Correction005 makes no additional timing amendment.

The full nested identity/start/failure/archive schemas, registered path parser table, partial-response behavior, bounded generated-start response, failure retirement procedure, concrete wrapper/serialization code, source diff and inverse are not independently validated implementation artifacts. The proposal correctly defers them. Its readback of a writer's generated self-report authenticates the saved bytes only within the proposed Main/tool trust model; it does not authenticate the truth or completeness of the process census.

“Blocks retained” accurately preserves both decisive barriers:

- **Continuous accounting:** startup and frame snapshots cannot exclude transient children/threads or unseen shell/PTY/transport processes. No complete continuous accounting and retirement facility has been established for this topology. Writer exit0 is not proof of every wrapper's retirement. The exact `B+max(1,H)≤8` resource requirement remains; choosing a fixed H or silently accepting self-report as complete would be an unauthorized weakening.
- **Terminal archival:** no writer can persist the tool return reporting its own eventual exit before that exit; adding an archiver repeats the same terminal dependency. A finite external Main/tool transcript boundary or atomic durable-return primitive remains necessary and unadopted. This is a limitation of the recursive archival scheme, not a claim that terminal recording is universally impossible.

Current `scripts/vipe_benchmark/s1_validation_contract.py::session_proof` still requires the v1 schema and fixed Correction008 authority; its `no_timeout_launch` and `R/launch-049-exec.py::main` still require the existing admission bindings and corrections001–015. Plan049 §8 adopts Correction016 as conditional planning authority only and does not waive this blocker. Correction005 correctly preserves that distinction. User approval of weaker UTC observations alone would address neither additional writer/topology trust nor final archival acceptance. Those decisions need exact explicit authorization or a demonstrated compliant platform facility before dependent work. Any later implementation still requires independent source/protocol/inverse review, fresh C4 and separate live clearance.
