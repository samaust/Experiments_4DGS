# Wrapper correction 002 — proposed bounded-clock and escrow amendment

**Status: plan-only proposal; not adopted authority or launch clearance.** The current C1–C3 assessment in `validation.md` and `validation-addendum-001.md` remains **not met**; C4 remains unverified. This proposal responds to the documented failure of `apply_patch` `Add File` to create exclusively and the absence of a verified monotonic clock at the `functions.exec` nested-call boundaries. It does not reinterpret a value that passes the current validator as a measured boundary stamp.

## Exact proposed authority change

Retain Correction008's `session-bound/v1` trust substitution, actual opaque handle, sole driver session, driver-local identity rechecks, readiness, two final empty same-handle live polls (`pre_admission`, `at_admission`), `ADMIT\n` correlation and outer terminal/owned-retirement proof. Amend only its evidence topology and clock representation: permit **one** already-started, persistent Main escrow writer process/session during the live driver, fully charged in the owned resource census, and replace the claimed exact Main UTC/monotonic call-boundary stamps with causal UTC bounds and tool-native elapsed metadata. This explicitly changes Correction008 §1's no-new-process rule, §3's exact stamp meaning, and its §4 final-poll evidence procedure. The writer is an evidence transport, never a second driver, PID observer, independent kernel attestor, or source of session liveness. Its process identity, thread count, ownership, readiness, failure and retirement must be recorded; if ownership/charge cannot be established in the applicable namespace(s), no driver starts. Preserve `B+max(1,H)≤8` at every creation/admission boundary, accounting for the writer and any transport wrapper/child rather than assuming `H=0`. The present contract requires `H=0`; the amendment must change its exact capacity correlation to the reviewed writer-inclusive value without weakening the bound or driver root/thread checks. Whether the available tool bridge can deliver arbitrary exact JSON to a persistent non-echoing writer and obtain a reliable readback acknowledgment is **unverified**. This document claims no working facility.

Proposed **event v2** is `plan049-session-tool-event/v2`, with exact top-level keys `{schema,kind,index,ordinal,role,tool,arguments,result,timing,raw_escrow,output_sha256}`. It removes v1 `started`/`returned`, rather than filling them with estimates. `arguments` and `result` are the unprojected native JSON objects of the one actual tool call, including the actual positive integer `session_id` and any native `wall_time_seconds`; preserve output exactly, including CR/LF and Unicode. `raw_escrow` is a strict `{path,bytes,sha256}` record for the **original serialized arguments/result/handle envelope** (plus kind/index/ordinal), saved before event construction. `timing` has exactly `{before_call_utc,after_escrow_utc,native_wall_time_seconds,monotonic_boundary_status}`. The UTC strings are timezone-aware UTC observations: one immediately before invoking the nested call and one only after raw escrow has been exclusively committed and read back. Thus `before_call_utc ≤ actual call start ≤ actual return ≤ after_escrow_utc`; neither string is labeled the exact call boundary. `native_wall_time_seconds` equals the native `result.wall_time_seconds` when present as a finite nonnegative number, otherwise `null`; it is elapsed tool metadata, **not a monotonic timestamp, whole-tree CPU time, or a clock origin**. `monotonic_boundary_status` is exactly `unmeasured`; no numeric monotonic boundary value is invented. Any missing UTC observation, reversed bound, lossy JSON serialization, absent/malformed native field, envelope mismatch, truncated tool output, or output-hash mismatch rejects the event. The unchanged UTF-8 SHA-256 covers `result.output` exactly. Cross-event causal ordering is checked using bounds and actual call sequence; overlapping broad bounds cannot be turned into a fabricated exact order.

Proposed **proof v2** is `plan049-session-proof/v2`: keep every v1 field and value, including `proof_mode:session-bound/v1`, `cross_namespace_kernel_verified:false`, fixed driver/request/admission paths, contiguous role sequence, sole complete readiness line/hash and exact same-handle argument/return checks; add exact strict file records `evidence_model_correction` (this proposal only after adoption) and `evidence_model_authorization` (a new explicit user authorization note). Require every event v2 `raw_escrow` record to resolve to a unique, exclusive file at a fixed attempt/ordinal path and byte-compare it to the event's native objects and handle. The proof binds v2 event files, which bind escrows. Correction008 remains the proof's existing `correction` record and its fixed authorization remains `user_authorization`; these new records do not erase the historical authority chain. Extend the exact admission `bindings` and prospective note bindings with the two new authority records and the writer identity/charge record; keep the current fixed `addenda` sequence and its source/dispatch bindings intact. A versioned writer record must prove one writer session/identity, charge, start-before-driver and retirement, without becoming an identity substitute for the driver. The exact new JSON keys, paths and equality checks require independent source review before adoption.

## One writer and one-way evidence order

Before a driver call, verify a fresh, unoccupied attempt index across **all** indexed families: identity, admission, launch note, driver start/stdout/stderr, diagnostic/aggregate directories, Main launch state/start/terminal/cleanup/outcome, session events/proof/send/poll/terminal, raw escrows, writer state/partial/failure records and any correction-specific output. Any occupied name retires that candidate; use a strictly higher index than retired diagnostic007. Start and identify the sole persistent writer before the driver, prove its exclusive-create/fsync/close/readback protocol on synthetic data, establish no echo/truncation/transport ambiguity for the maximum permitted envelope, and charge its process, threads and any wrappers continuously. Its private framed input protocol must carry the exact JSON bytes without shell-argument interpolation, and its acknowledgment must be tied to the exclusive pathname, byte count, digest, exact handle and bytes actually read back from disk. A digest alone is not evidence that the writer received the entire native envelope; Main must compare the readback envelope/bytes to the original return. A fixed transport size limit is acceptable only as an explicit fail-closed limit, never as proof that arbitrary returns fit.

For each `exec_command` or same-handle empty `write_stdin` call, take the `before_call_utc` observation, invoke once, and make the writer transfer the **first dependent action** after return. Keep the exact returned handle in the same Main invocation until escrow acknowledgment; no readiness parsing, hashing, poll, proof or admission is allowed first. No design can make serialization/transport infallible before disk persistence, so C1 means **successfully escrowed returns only**. On lossless serialization/transport, the writer uses `O_CREAT|O_EXCL` at a fresh attempt/ordinal path, writes all bytes, fsyncs the file, closes it, reads back exact bytes (and durably records directory creation if required by the filesystem), and returns a verified acknowledgment. Main compares exact original arguments/result/handle to readback before using them. Then sample `after_escrow_utc`, hash the output, exclusively write/fsync/read back the event, and bind its escrow record. The writer itself must stay ready through the last pre-admission escrow; no per-event writer/helper process is allowed.

The dependency graph is **raw escrow → event → proof → admission → `ADMIT\n` send record → driver note/exec-start/capture/outer terminal**. The proof binds the ordered pre-admission event records and static authority/identity records, but not admission bytes; it names only the fixed future admission path. Admission binds the already final proof record. Driver's post-ADMIT prospective note binds admission, proof, authority, and event/escrow records. Separate send/terminal records bind the proof/admission hashes after the send; neither is retroactively inserted into the proof. This preserves the present validator's non-circular manifest/proof/admission order. Between the final `at_admission` poll and `ADMIT\n`, only its escrow/event, proof validation/readback, fresh bound-byte checks, admission/readback, and required same-session checks are allowed. If the writer cannot finish these without an unrelated tool job or an uncharged helper, the attempt cannot admit.

Serialization exception, transport overflow/timeout/loss, writer death, existing target, partial write, fsync/close/readback failure, ambiguous acknowledgment, mismatch, missing exact handle, tool error, terminal/mismatched session, or post-poll interruption means **no valid event, proof, admission or ADMIT**. Mark the candidate retired even if its partial file is unreadable. Reconcile only through the exact handle returned by that call or a previously escrowed equal handle; if exact handle/liveness is uncertain, stop with ownership uncertainty rather than guess. If it is affirmatively the same live session, send `ABORT\n` once, capture its actual result and outer terminal, retire writer and driver, and retain all partial evidence. An ambiguous send is reconciled on that same handle before any fresh attempt. Do not replay the original tool call or reuse an occupied index. A failed persistence path cannot satisfy C1 merely because retirement succeeds.
