## Findings against the current implementation

**F3-0 — P1: CPU acceptance is blocked by shared fixture drift.** The rerun confirms the exact diagnosis above. Nine lifecycle methods never reach their intended assertions. The passing typed-scope test rejects malformed flags before preservation; it is not evidence that a valid lifecycle succeeds. This remains part of F2-1/F2-6.

**F3-1 — P1: admission/lifecycle integration and preservation remain unproven.** `preservation` now separates scientific bytes, exact ledger prefix/chain and loop status, checks the correction against the baseline, and restricts appended event types (`s1_recovery.py:208–265`). This removes the previous whole-ledger-hash contradiction in design. However, it checks only the bookkeeping policy string; it does not verify old/new status transition records or the current status against them. The appended-event filter alone is not a complete lifecycle/binding validator. Tests still fabricate admission (`tests/...s1_recovery.py:100–105`), mock `AssetBundle`/source membership, and mock numerical/runtime qualification at resolution. No passing disposable `common_admission → execute_s1_recovery → registration → reservation → supervisor → finish → result_record` test exists. Add that path and boundary mutation, concurrency, block/continuation and replay tests with real guards and fake workers/resources. Keep original failures and unrelated allocations unchanged.

**F3-2 — P1: loaded source/native evidence is not fully matched to E1.** `qualify_runtime` now checks the manifest schema, interpreter, nested hashes, required module names, forbidden roots/modules and installed inventory (`s1_evidence.py:268–308`). But an entry is compared with the admitted inventory only *if its path is present there*. Mandatory inventory membership is enforced only for torch/torchvision/numpy. GroundingDINO/SAM source records are not matched to the admitted asset trees, and any entry flagged as a mapped native library satisfies the native-presence condition. The guard does not require the appropriate admitted E1 native import/build identities. Current self-consistent hashes therefore do not establish the full admitted source/native relationship. Add successful and changed-source/native CPU fixtures and compare against admitted source, inventory and import/build evidence without new imports or forwards.

**F3-3 — P1: cleanup conflicts with a legitimate failed first-result record.** The supervisor unconditionally calls `first_record(..., 'not_reached', error=..., stage='supervisor_cleanup')` (`supervisor.py:243–254`). If the worker already published `failed` or a different `not_reached` record, `first_record` permits reuse only when the entire newly generated value is identical (`s1_evidence.py:45–56`); status/error/stage and usually elapsed time differ. A normal early failure consequently acquires a spurious publication-conflict error. Reconcile and reference existing verified failure evidence without replacing it; advancement must still require a verified pass. Also synchronize the supervisor's local `stop_required`/failure classification with publication failures: line 254 updates the ledger evidence but not the local flag later passed to `SupervisionFailure` at line 265. Add clean early-failure and publication-conflict tests. This is a static control-flow finding, not a new executed lifecycle probe.

**F3-4 — P1: durable block/partial/terminal handling has remaining holes.** Moving initial binding inside the controller's `try/finally`, separate pre-dispatch filenames, produced/qualified row files and partial runtime are improvements. But `terminal_receipt` verifies/parses authorization before its pre-reservation branch (`s1_recovery.py:345–364`), so unreadable, changed or malformed authorization can prevent block evidence. Result/partial parsing also occurs outside its guarded preservation block (lines 365–377); a corrupt partial or result can abort terminal publication. Counts label files as qualified without requalifying partial rows. `partial-runtime.json` is written only after the first row, leaving earlier runtime failures without that durable runtime record. The worker's final `failure.json` write can itself replace the primary exception (`basketball_vipe_worker.py:60–64`). Complete minimal block evidence independent of failed bindings, partial-evidence reconciliation, and primary-error preservation. Cover missing result, later-row failure, abrupt death and publication failure; do not infer confirmed cleanup from absent evidence.

**F3-5 — P1: the full acceptance/publication budget remains unenforced.** The new immediate prelaunch time check and acceptance timer improve coverage, but `execute_s1_recovery` calls `terminal_receipt` after `supervise` has finished and charged elapsed time (`execution.py:641–648`). That receipt re-enters `resolved_result` and validates all 510 rows outside the supervisor deadline/resource timer. `bounded_acceptance` also runs the full resource sampler inside a repeating 50 ms signal handler (`supervisor.py:78–95`); slow sampling can be interrupted by another sampling callback, and Python signal delivery does not establish a hard bound on blocking native work. Its resource checks omit GPU ownership checks during the guarded prelaunch/acceptance interval. Use a bounded, non-reentrant monitoring/validation design and include terminal publication in the charged allocation. Test slow hashing/decompression/publication, expiration before launch, ownership/cap changes and cleanup reserve. No such S1-specific test ran here.

**F3-6 — P2: numerical/envelope corrections need successful and adversarial real-guard coverage.** The source now checks native resize/normalization, processed RGB shape/finiteness, pixel boxes, detection id/index, independently captured phrase bytes, full first-result envelope and strict passed-record reuse. The qualification subtest still deliberately omits `diagnostics` (test lines 276–277); it does not test numerical corruption. Surviving semantic lookup also accepts Python negative indexing and omits surviving id/box consistency (`s1_evidence.py:197–200`); check the native skipped/overwritten-detection mapping without assuming object IDs always equal query indices. Add valid zero-detection, tie/ambiguity, skipped/overwritten, processed-RGB/box/phrase mutations, nested runtime, envelope and publication cases. Preserve native thresholds and refinement/tracking behavior.

**F3-7 — P2: receipt validation does not reconcile subtests or the prescribed aggregate.** `validation_record` now verifies method identities against source AST and rejects the old one-test command-name trick (`s1_recovery.py:59–85`). It still ignores recorded subtests and per-suite totals, and unions cases across receipts without requiring the prescribed aggregate execution. A contradictory receipt with passing method counters and failed subtest records is not rejected by this logic.
