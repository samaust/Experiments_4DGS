## Evidence and decision

Attempt008's original visible Main `write_stdin` result at event ordinal 1 contains one echo of the structured start frame sent through that same retained tool handle, then one readiness line. `arguments.chars` contains one JSON line ending in LF; the PTY rendered only that terminal LF as CRLF in the echoed output. The event copy and its readback matched the preserved original Main result. The present `session_proof` rejects the complete output because its final comparison accepts only bootstrap plus readiness with LF or CRLF. No `ADMIT\n` was sent. The session was interrupted by its retained handle and ended with outer exit 1; attempt008, its path, identity request and evidence are consumed historical records and cannot be resumed, admitted, rewritten or reused. Diagnostic005 remains a historical failure.

The prospective correction is local to `session_proof` in `scripts/vipe_benchmark/s1_validation_contract.py`. After its existing structured-frame, exact handle, event order, live-result, hash, truncation and readiness checks, take the **actual ordinal-1** `arguments.chars` string. Require precisely one terminal LF and no earlier literal LF or CR. Define the only new echo as `chars[:-1] + '\r\n'`. For the echo branch, require the complete ordinal-1 output to equal `echo + readiness_line + terminator`, with the readiness terminator independently equal to one of the already permitted `\n` or `\r\n`, and require its readiness-completion ordinal to be 1. Compare the entire concatenated transcript to `bootstrap + echo + readiness_line + terminator`; later poll output remains empty by that equality. Retain the existing no-echo `bootstrap + readiness_line + terminator` acceptance, including split readiness, bootstrap validation, complete-output equality and readiness-completion event check. The comparison is never to a substring. No strip, search, parse-and-reserialize, general newline conversion, arbitrary shell echo, extra output or relaxed output hash is permitted. The echo is derived from the validated sent string, not from a copy's reparsed JSON or a historical frame constant. Original Main tool call/result objects and per-event hashes remain unchanged and are compared with checked file copies at the finite Main transcript trust boundary.

There is an unavoidable distinction in the negative cases: a wholly absent echo followed by an otherwise exact readiness line is the already accepted no-echo transcript and cannot be rejected by `session_proof` without changing that existing behavior. For the **observed echo-bearing Main result**, omission from its checked copy must fail original-result/readback equality. A partial echo, changed or duplicated echo, or other unmatched bytes must fail complete-output comparison. This is the precise meaning of “missing echo rejected” in this correction; no test may claim that the validator can distinguish an otherwise valid bare readiness line from a lost echo without independent original-result evidence.
